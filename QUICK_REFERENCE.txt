1. LLM PROVIDER SYSTEM (app/core/llm/)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📋 ABC: LLMProvider (base.py)
├─ generate_content(prompt, model, system_instruction, tools, stream, **kwargs)
│  └─ Returns: Dict{content, tool_calls, usage} | Generator
└─ get_token_count(prompt, model) → int

🔧 Implementations:
├─ GeminiProvider (gemini.py)
│  ├─ Retry: 3x with exponential backoff (2s base, for 429/503)
│  ├─ Special: Interactions API for deep-research models
│  ├─ _call_with_retry() - Exponential backoff logic
│  ├─ _call_via_interactions_api() - Separate 90s timeout
│  └─ _format_tools() → google.genai.types.FunctionDeclaration
│
└─ OllamaLLMProvider (ollama_llm_provider.py)
   ├─ Local models via Ollama API
   ├─ OpenAI-compatible tool format
   └─ Auto-injects Skills

⛓️  Fallback Mechanism (model_fallback.py: ModelFallbackExecutor)
├─ generate_with_fallback() - Auto-switch on "model not found" errors
├─ get_best_available(task_type) - Returns first available model
├─ mark_unavailable(model_id) - 5-minute blacklist (TTL configurable)
│
├─ Task-Specific Chains:
│  ├─ CHAT: gemini-3-flash → gemini-2.5-flash → gemini-2.0-flash
│  ├─ CODER: gemini-3.1-pro → gemini-3-pro → gemini-2.5-pro → gemini-2.5-flash
│  ├─ RESEARCH: ...pro → deep-research-pro (Interactions API) → ...
│  ├─ PAINTER: gemini-3.1-flash-image → gemini-2.0-flash-exp
│  └─ (+ 11 more task types)
│
└─ Error Patterns: 404, "not found", "model.*not.*exist", "Interactions API"

🏭 Factory (factory.py)
├─ create_agent(api_key, model_id) → UnifiedAgent [Gemini]
├─ create_local_agent(model, base_url) → UnifiedAgent [Ollama]
├─ create_langgraph_agent(...) → LangGraphAgent [StateGraph]
├─ create_multi_agent(...) → MultiAgentOrchestrator [Researcher/Writer/Critic]
└─ _build_registry(api_key, full=True) → ToolRegistry


2. AGENT SYSTEM (app/core/agent/)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📋 ABC: Agent (base.py)
├─ run(input_text, context) → Union[AgentResponse, Generator[AgentStep]]
└─ llm: LLMProvider

🤖 Implementations:
├─ UnifiedAgent (unified_agent.py) - Main ReAct while-loop (15 steps max)
│  ├─ run() → ReAct loop: reason → decide → execute tools → validate → respond
│  ├─ Features: PII filter, output validation, tool routing, feedback learning
│  ├─ MAX_STEPS = 15
│  └─ MAX_VALIDATION_RETRIES = 1
│
├─ LangGraphAgent (langgraph_agent.py) - StateGraph based
│  ├─ Nodes: reason → call_tools → validate → respond
│  ├─ MemorySaver checkpoints for multi-turn
│  └─ Preserves PII filter & output validation
│
└─ MultiAgentOrchestrator (multi_agent.py) - Multi-role orchestration
   ├─ Roles: RESEARCHER, WRITER, CRITIC, REVISE
   └─ Topologies: sequential, critic_loop, parallel

📌 Plugin System:
├─ Base: AgentPlugin (ABC, base.py)
│  ├─ name: str (property)
│  ├─ description: str (property)
│  └─ get_tools() → List[Dict{name, description, func, parameters}]
│
├─ Registration: ToolRegistry.register_plugin(plugin)
│
└─ 24 Plugins:
   ├─ Core (always): basic_tools, file_editor, search, system_tools, system_info
   ├─ Optional (try-catch): memory_tools, productivity, web_tools_bridge
   └─ Full (UnifiedAgent): alerting, annotation, auto_remediation, chart_vision,
      configuration, data_process, doc_gen, file_converter, image_process,
      network, performance_analysis, script_generation, system_event_monitoring,
      template_fill, trend_analysis

🔧 Tool Registry (tool_registry.py: ToolRegistry)
├─ register_tool(name, func, description, parameters)
│  └─ Auto-generates JSON schema from function signature
├─ register_plugin(plugin)
├─ get_definitions() → List[Dict] [for LLM]
├─ execute(tool_name, tool_args) → Any
│  └─ ThreadPoolExecutor, 60-second timeout per tool
└─ _generate_schema(func) → Dict
   └─ Uses inspect.signature() + get_type_hints()
   └─ Maps: int→INTEGER, float→NUMBER, list→ARRAY, dict→OBJECT


3. ROUTING/DISPATCH SYSTEM (app/core/routing/)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🎯 SmartDispatcher (smart_dispatcher.py)
├─ Hybrid routing: AI first → fallback to local algorithms
├─ analyze(user_input) → (task_type, confidence, source)
├─ LRU cache: 128 entries max, thread-safe
├─ USE_AI_ROUTER: toggle for AI classification
└─ Task corpus: 30+ task types with example prompts

🧠 IntentAnalyzer (intent_analyzer.py)
├─ analyze(messages, user_input, client) → str (rewritten instruction)
├─ Detects: repeat patterns, pronouns, modifications, document references
├─ Trigger patterns:
│  ├─ Repeat: "重复任务", "再做一遍", "try again"
│  ├─ Pronouns: "刚才", "这个", "上一个", "之前"
│  ├─ Modifications: "继续", "修改", "优化一下"
│  └─ References: "第3点", "其中第二步"

📍 AIRouter (ai_router.py)
├─ classify(client, user_input, timeout=2.0) → (task_type, confidence, source)
├─ Uses: gemini-2.0-flash-lite for fast classification
├─ Cache: 100 entries LRU
└─ 14 Task Types: PAINTER, FILE_GEN, DOC_ANNOTATE, RESEARCH, CODER, FILE_SEARCH,
   SYSTEM, AGENT, WEB_SEARCH, CHAT, + disambiguation rules

🏗️  Other Components:
├─ LocalModelRouter - Ollama model initialization
├─ TaskClassifier - Local task classification
├─ TaskDecomposer - Complex task decomposition
├─ LocalPlanner - Execution planning
├─ ToolRouter - Filters tools by task type
└─ PlanExecutor - Executes task plans


4. SECURITY SYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🛡️  PII Filter (pii_filter.py: PIIFilter)
├─ Thread-safe static class (mask_map is local)
├─ mask(text, config=None) → MaskResult
│  ├─ masked_text: Deidentified (safe for cloud)
│  ├─ original_text: Input
│  ├─ mask_map: Dict[placeholder → original] for restoration
│  ├─ stats: {label → count}
│  └─ has_pii: boolean property
│
├─ restore(masked_text, mask_map) → str
├─ has_pii(text, config) → bool
└─ add_custom_keyword(config, keyword) → PIIConfig

📋 Detectors (9 types, regex-based):
├─ 手机号 (China mobile): 1[3-9]\d{9}
├─ 固话 (Landline): 0\d{2,3}[-\s]?\d{7,8}
├─ 身份证 (ID card): 18-digit with region/date/checksum
├─ 银行卡 (Bank card): 16-19 consecutive digits
├─ 邮箱 (Email): Standard email regex
├─ IP地址 (IPv4): 4 octets
├─ 姓名 (Chinese name): Heuristic with prefix words (叫/是/给/向/找)
├─ 地址 (Address): Province/city/district/street pattern
└─ 证件号 (Passport/HK/Macau): E/H/M + 7-9 alphanumeric

⚖️  Output Validator (output_validator.py: OutputValidator)
├─ validate(text, skill_id=None, original_prompt=None) → ValidationResult
├─ Action: "PASS" | "WARN" | "REFORMAT" | "RETRY" | "BLOCK"
│
├─ Validation Checks (in order):
│  1. Refusal patterns (model refused)
│  2. Code substitute (claims inability, provides code)
│  3. Realtime inability (no real-time data, doesn't call web_search)
│  4. Truncation endings ("...", "（未完）", "to be continued")
│  5. Internal leak detection (PII placeholders, system prompt)
│  6. Repetition detection (same sentence >4 times)
│  7. Format checking (if skill_id provided)
│  8. Completeness checking (not empty, minimum length)
│
├─ Actions:
│  ├─ PASS: All OK, return directly
│  ├─ WARN: Minor issues (too short), log but return
│  ├─ REFORMAT: Content OK but format wrong → Auto-format
│  ├─ RETRY: Quality issues, re-request (up to MAX_VALIDATION_RETRIES)
│  └─ BLOCK: Severe security issues (prompt leak), stop
│
└─ configure_llm_judge(client, model_id, timeout) - Optional LLM judgment

🖥️  Desktop App (src/koto_app.py: PyWebView)
├─ Architecture: Flask backend (127.0.0.1:5000) + PyWebView native window
├─ File Structure (Frozen by PyInstaller):
│  ├─ APP_ROOT: exe directory (persistent: chats/, config/, workspace/)

├─ Entry: koto_setup.py (first-run wizard)

├─ Data Files:
│  ├─ web/templates/, web/static/ (frontend)

│  ├─ assets/ (icons: .ico, .png, .svg)

│
├─ Hidden Imports: tkinter, flask, flask_cors, werkzeug, google.genai, langchain, langgraph
└─ Excludes: pytest, tests, torch, tensorflow

🌐 Server Mode (src/server.py)
├─ Pure ASGI/WSGI (no desktop UI)
├─ Dev: python server.py (Flask dev server)
├─ Prod: gunicorn -w 2 -b 0.0.0.0:5000 server:app
├─ Environment:
│  ├─ KOTO_PORT

   3. Init logging (app/core/logging_setup.py)

   5. Load Flask app (web/app.py)
