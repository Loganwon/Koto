                       KOTO - EXECUTIVE SUMMARY
                     Core Systems Analysis & Architecture
═════════════════════════════════════════════════════════════════════════════════

OVERVIEW
────────
Koto is a sophisticated multi-modal AI assistant with desktop, web, and cloud 
deployment capabilities. Core architecture combines:
  • LLM Provider abstraction with automatic fallback
  • Unified agent framework with 24 specialized plugins
  • Hybrid routing (AI + local algorithms)
  • Privacy-preserving PII filtering
  • Output quality validation
  • Multi-deployment support (PyWebView, Docker, PyInstaller)

KEY METRICS
───────────
  • Plugins: 24 (13 core + full, 5 optional)
  • Task Types: 30+ (CHAT, CODER, PAINTER, RESEARCH, etc.)
  • Fallback Chains: 14 task-specific model chains
  • LLM Providers: 2 (Gemini + Ollama)
  • Agent Types: 3 (UnifiedAgent, LangGraphAgent, MultiAgentOrchestrator)
  • Security Detectors: 9 PII types
  • Validation Checks: 8 output quality checks
  • Deployment Modes: 3 (Desktop, Server, Docker)


TIER-1: LLM PROVIDER SYSTEM
═══════════════════════════════════════════════════════════════════════════════

PURPOSE
  Provides unified interface to multiple LLM backends with automatic fallback
  and retry logic.

ABC: LLMProvider
  generate_content(prompt, model, system_instruction, tools, stream) 
    → Dict{content, tool_calls, usage} | Generator

IMPLEMENTATIONS
  ┌─ GeminiProvider ────────────────────────────────────────────────────┐
  │ • Uses google.genai.Client SDK                                     │
  │ • Retry: 3 attempts with exponential backoff (2s base, 429/503)    │
  │ • Special Interactions API path for deep-research models           │
  │ • Tool format: google.genai.types.FunctionDeclaration              │
  │ • Streaming support with token-level granularity                   │
  └─────────────────────────────────────────────────────────────────────┘

  ┌─ OllamaLLMProvider ─────────────────────────────────────────────────┐
  │ • Local models via Ollama OpenAI-compatible API                    │
  │ • Tool format: OpenAI-compatible (supports qwen3, llama3.1, etc.)  │
  │ • Auto-injects Koto Skills into system prompt                      │
  │ • No API key required, runs locally                                │
  └─────────────────────────────────────────────────────────────────────┘

FALLBACK MECHANISM (ModelFallbackExecutor)
  Strategy: Task-specific fallback chains with circuit breaker
  
  Example (CODER task):
    1st attempt: gemini-3.1-pro-preview
      ↓ (if "model not found" error)
    2nd attempt: gemini-3-pro-preview
      ↓ (if "model not found" error)
    3rd attempt: gemini-2.5-pro-preview
      ↓ (if "model not found" error)
    [fallback continues...]
  
  Circuit Breaker: After N consecutive cascading failures, exponentially
                   back off (5s → 10s → 20s → ... → 120s max)

FACTORY (factory.py)
  • create_agent() - Full UnifiedAgent [Gemini backend]
  • create_local_agent() - UnifiedAgent [Ollama backend]
  • create_langgraph_agent() - StateGraph agent [Gemini backend]
  • create_multi_agent() - Multi-role orchestrator [Gemini backend]

FILES
  • app/core/llm/base.py - ABC definition
  • app/core/llm/gemini.py - GeminiProvider (415 lines)
  • app/core/llm/ollama_llm_provider.py - OllamaLLMProvider
  • app/core/llm/model_fallback.py - Fallback executor (346 lines)
  • app/core/agent/factory.py - Agent factory (300 lines)


TIER-2: AGENT SYSTEM
═══════════════════════════════════════════════════════════════════════════════

PURPOSE
  Core agent loop implementation with plugin architecture for extensibility

ABC: Agent
  run(input_text, context) → Union[AgentResponse, Generator[AgentStep]]

IMPLEMENTATIONS

  ┌─ UnifiedAgent (41KB) ──────────────────────────────────────────────┐
  │ Main agent loop (ReAct while-loop, max 15 steps):                 │
  │   1. Reason & Plan  - LLM decides action                           │
  │   2. Tool Decision  - Check if tools needed                        │
  │   3. Execute Tools  - Call tools with ThreadPoolExecutor (60s/tool)│
  │   4. Validate       - OutputValidator checks response              │
  │   5. Respond        - Return final answer to user                  │
  │                                                                    │
  │ Features:                                                           │
  │   ✓ PII demasking (input → mask → send to cloud → unmask output) │
  │   ✓ Output validation (refusal, truncation, leak detection)       │
  │   ✓ Tool routing (filters tools based on task type)               │
  │   ✓ Shadow learning (async feedback collection)                   │
  │   ✓ Skill injection (automated)                                   │
  │                                                                    │
  │ Configuration:                                                      │
  │   MAX_STEPS = 15                                                   │
  │   MAX_VALIDATION_RETRIES = 1                                       │
  │   enable_pii_filter = True                                         │
  │   enable_output_validation = True                                  │
  │   use_tool_router = True                                           │
  │   tool_router_max = 20 (show top 20 tools to LLM)                 │
  └─────────────────────────────────────────────────────────────────────┘

  ┌─ LangGraphAgent ────────────────────────────────────────────────────┐
  │ StateGraph-based ReAct (LangGraph requirement)                     │
  │   • Nodes: reason → call_tools → validate → respond               │
  │   • MemorySaver checkpoints for multi-turn conversations          │
  │   • Preserves PII filter + output validation                       │
  │   • Streaming support with token-level granularity                 │
  │   • Requires: langgraph, langchain-core, langchain-google-genai   │
  └─────────────────────────────────────────────────────────────────────┘

  ┌─ MultiAgentOrchestrator ───────────────────────────────────────────┐
  │ Multi-role collaboration (Researcher → Writer → Critic)           │
  │   • Role: RESEARCHER - Deep analysis                              │
  │   • Role: WRITER - Draft content                                  │
  │   • Role: CRITIC - Review & feedback                              │
  │   • Role: REVISE - Refinement loop                                │
  │                                                                    │
  │ Topologies:                                                         │
  │   • sequential - Linear pipeline                                   │
  │   • critic_loop - Writer → Critic feedback → Revision (iterative)│
  │   • parallel - All agents run simultaneously                       │
  └─────────────────────────────────────────────────────────────────────┘

PLUGIN SYSTEM

Base Class: AgentPlugin (ABC, base.py)
  Properties:
    • name: str
    • description: str
  Methods:
    • get_tools() → List[Dict{name, description, func, parameters}]

Registration: ToolRegistry.register_plugin(plugin)
  1. Calls plugin.get_tools()
  2. Validates each tool has 'name' and 'func'
  3. Auto-generates JSON schema from function signature
  4. Registers with LLM for function calling

  Optional (Try-Catch):
    6. MemoryToolsPlugin - Long-term memory management (P2 Priority)
    7. ProductivityPlugin - Calendar/tasks/reminders
    8. WebToolsBridgePlugin - Browser automation

  Full Suite (UnifiedAgent):
    9. AlertingPlugin - Create alerts/notifications
   10. AnnotationPlugin - Document annotation
   11. AutoRemediationPlugin - Auto-fix issues
   12. ChartVisionPlugin - Vision analysis for charts
   13. ConfigurationPlugin - System configuration
   14. DataProcessPlugin - Data transformation/cleaning
   15. DocGenPlugin - Document generation
   16. FileConverterPlugin - Format conversion
   17. ImageProcessPlugin - Image manipulation
   18. NetworkPlugin - Network operations
   19. PerformanceAnalysisPlugin - Performance metrics
   20. ScriptGenerationPlugin - Code generation
   21. SystemEventMonitoringPlugin - Event monitoring
   22. TemplateFillPlugin - Word template filling
   23. TrendAnalysisPlugin - Trend detection
   24. SkillToolsPlugin - Skill adapter (auto-injects all active Skills)

Tool Registry (ToolRegistry)
  Methods:
    • register_tool(name, func, description, parameters)
    • register_plugin(plugin)
    • get_definitions() → JSON schemas for LLM
    • execute(tool_name, tool_args) → Result with 60s timeout
    • _generate_schema(func) → Auto JSON schema from function

TIER-3: ROUTING/DISPATCH SYSTEM
═══════════════════════════════════════════════════════════════════════════════

PURPOSE
  Analyze user input and intelligently route to appropriate task type and tools

COMPONENTS

  ┌─ SmartDispatcher ──────────────────────────────────────────────────┐
  │ Hybrid routing strategy:                                           │
  │   1st: Try AI-based classification (fast, smart)                   │
  │   2nd: Fall back to local algorithms (reliable, deterministic)    │
  │   3rd: Return cached result (if same query seen before)           │
  │                                                                    │
  │ Cache: LRU with 128 entries max, thread-safe                      │
  │ USE_AI_ROUTER: Boolean toggle                                     │
  │ Task corpus: 30+ task types with example prompts                  │
  └─────────────────────────────────────────────────────────────────────┘

  ┌─ IntentAnalyzer ────────────────────────────────────────────────────┐
  │ Rewrites ambiguous multi-turn inputs to standalone instructions:  │
  │                                                                    │
  │ Input (ambiguous):   "继续上一个任务"                              │
  │ Output (clear):      "[Reconstructed previous task with updates]" │
  │                                                                    │
  │ Detects & rewrites:                                                │
  │   • Repeat patterns - "再做一遍", "重复任务"                        │
  │   • Pronouns - "那个", "这个", "上一个"                             │
  │   • Modifications - "继续", "改成", "优化一下"                      │
  │   • References - "第3点", "其中第二步"                              │
  └─────────────────────────────────────────────────────────────────────┘

  ┌─ AIRouter ─────────────────────────────────────────────────────────┐
  │ Fast AI-based task classification (2s timeout)                    │
  │   Model: gemini-2.0-flash-lite                                     │
  │   Cache: 100 entries LRU                                           │
  │   Returns: (task_type, confidence, source)                         │
  │                                                                    │
  │ 14 Task Types (+ disambiguation rules):                           │
  │   • PAINTER - Generate AI art/images                              │
  │   • FILE_GEN - Create Word/PDF/Excel/PPT                          │
  │   • DOC_ANNOTATE - Annotate/proofread documents                   │
  │   • RESEARCH - Deep systematic analysis                           │
  │   • CODER - Code/programming/data visualization                   │
  │   • FILE_SEARCH - Find files on disk                              │
  │   • SYSTEM - Open/close applications                              │
  │   • AGENT - Execute operations (message/reminder/buy tickets)     │
  │   • WEB_SEARCH - Real-time data (weather/stocks/news)            │
  │   • CHAT - General conversation                                   │
  │   (+ COMPLEX, MULTI_STEP, VISION, FILE_OP, FILE_EDIT)            │
  │                                                                    │
  │ Special Rules (key distinctions):                                 │
  │   • "作图" → CODER not PAINTER (data chart vs AI art)             │
  │   • "帮我找文件" → FILE_SEARCH not SYSTEM (find file, not app)    │
  │   • "深入研究" → RESEARCH not CHAT (systematic vs casual)         │
  │   • "帮我买票" → AGENT not WEB_SEARCH (action vs information)     │
  └─────────────────────────────────────────────────────────────────────┘

Other Components:
  • LocalModelRouter - Manages local Ollama model initialization
  • TaskClassifier - Non-AI task classification (local algorithms)
  • TaskDecomposer - Breaks complex tasks into subtasks
  • LocalPlanner - Creates execution plans
  • ToolRouter - Filters available tools based on task type
  • PlanExecutor - Executes task plans sequentially

TIER-4: SECURITY SYSTEM
═══════════════════════════════════════════════════════════════════════════════

PURPOSE
  1. Protect user privacy by masking PII before sending to cloud
  2. Ensure output quality and security

COMPONENTS

  ┌─ PIIFilter (pii_filter.py) ────────────────────────────────────────┐
  │ Local privacy-preserving masking (zero network calls)             │
  │ Thread-safe static class                                          │
  │                                                                    │
  │ Method: mask(text, config) → MaskResult                           │
  │   • Scans with pre-compiled regex                                 │
  │   • Replaces matches with <<label-N>> placeholders               │
  │   • Returns {masked_text, mask_map, stats}                        │
  │                                                                    │
  │ Method: restore(masked_text, mask_map) → str                      │
  │   • Replaces placeholders with original values                    │
  │   • Called when LLM response returns                              │
  │                                                                    │
  │ Detectors (9 types, regex-based):                                │
  │   1. 手机号 (China mobile) - 1[3-9]\d{9}                          │
  │   2. 固话 (Landline) - 0\d{2,3}[-\s]?\d{7,8}                     │
  │   3. 身份证 (ID card) - 18-digit with region/date validation     │
  │   4. 银行卡 (Bank card) - 16-19 consecutive digits               │
  │   5. 邮箱 (Email) - Standard email regex                         │
  │   6. IP地址 (IPv4) - 4 octets (disabled by default)             │
  │   7. 姓名 (Chinese name) - Heuristic with 9 prefix words         │
  │   8. 地址 (Address) - Province/city/district/street pattern      │
  │   9. 证件号 (Passport/HK/Macau) - E/H/M + 7-9 alphanumeric      │
  │                                                                    │
  │ Example:                                                           │
  │   Input:  "请给张伟发消息，电话13812345678，邮箱z@qq.com"       │
  │   Output: "请给<<姓名-1>>发消息，电话<<手机号-1>>，邮箱<<邮箱-1>>"│
  │   Map:    {<<姓名-1>>: "张伟", <<手机号-1>>: "13812345678", ...} │
  │                                                                    │
  │ Configuration: PIIConfig                                          │
  │   • mask_phone, mask_landline, mask_id_card, mask_bank_card      │
  │   • mask_email, mask_ip, mask_name, mask_address, mask_passport  │
  │   • custom_keywords: List[str] for user-defined sensitive words  │
  │   • log_stats: bool for logging statistics                        │
  └─────────────────────────────────────────────────────────────────────┘

  ┌─ OutputValidator (output_validator.py) ────────────────────────────┐
  │ Quality assurance on LLM responses                                │
  │                                                                    │
  │ Method: validate(text, skill_id, original_prompt) → ValidationResult│
  │   Action: "PASS" | "WARN" | "REFORMAT" | "RETRY" | "BLOCK"      │
  │                                                                    │
  │ 8-Check Validation Pipeline:                                      │
  │   1. Refusal Detection                                            │
  │      • Patterns: "I cannot", "我无法", "作为AI我不能"            │
  │   2. Code Substitute Detection                                    │
  │      • Claims inability then provides Python code                 │
  │   3. Realtime Inability                                           │
  │      • Admits no real-time data but doesn't call web_search      │
  │   4. Truncation Detection                                         │
  │      • Ends with "...", "（未完）", "to be continued"            │
  │   5. Internal Leak Detection                                      │
  │      • PII placeholders leaked, system prompt exposed             │
  │   6. Repetition Detection                                         │
  │      • Same sentence repeated >4 times                            │
  │   7. Format Checking (if skill_id)                               │
  │      • Validates against OutputSpec                               │
  │   8. Completeness Checking                                        │
  │      • Not empty, above minimum length                            │
  │                                                                    │
  │ Actions & Recovery:                                               │
  │   • PASS - All OK, return directly                                │
  │   • WARN - Minor issues (too short), log but return              │
  │   • REFORMAT - Format wrong → auto-format locally (markdown)     │
  │   • RETRY - Quality issues → re-request (max 1 retry)            │
  │   • BLOCK - Security issues → stop, report error                 │
  └─────────────────────────────────────────────────────────────────────┘

FILES
  • app/core/security/pii_filter.py - PII masking (310 lines)
  • app/core/security/output_validator.py - Output validation (300+ lines)
