# 文件即工作流：交互收敛方案

2026-10-20。设计原型，未部署到正式Office/WPS。最新方向为轻量交互入口与可展开的详细任务图：入口保持一行文件流与一个输入框，任务图完整表达来源、处理和交付，文件列表按需展开。

## 默认界面

1. 顶部Koto、文件入口、最近任务图标。
2. 一行文件流：资料数量 → 当前文档 → 预计交付类型，例如 XLSX · DOCX。点击文件流展开详细任务图，图中点交付文件再查看格式选择。
3. 一个要求/反馈输入框，底部只留“已选2段 · 51字”和一个主按钮。开始、停止、继续、发送反馈、生成结果随状态共用该按钮。
4. 执行中只出现当前一步的一句结果，例如“第1段已更新，等你检查”。选区摘要、文件摘要和历史都按需展开，不默认铺开。

列表表示工作区里有哪些文件，文件流表示本次任务使用什么、修改哪个目标以及交付什么。列表默认收起，点击文件入口或资料数量展开。展开时与文件流、输入框同时存在，不采用互相替换的标签页。工作台左侧放列表；窄侧栏将列表缩为上方的紧凑区域，输入框仍然保留，列表文件仍可直接拖入文件流。

日常入口不铺开节点说明、版本标记、重复交付摘要或单独进度工具栏。详细关系放在任务图里，操作保持同一个输入框和主按钮；收起图不切换任务、不清空输入或重置检查点。

## 详细任务图与轻量交互

- 图分为来源、处理、交付三层。例如项目数据 → 核对预算 → 预算明细表；客户访谈 → 提炼客户要点 → 客户摘要；当前选区 → 精简选中内容 → 原文更新。必要的跨分支引用通过连线表达。
- 原文修改与新建文件区分：季度报告是在原文件内更新，预算和摘要才是待生成文件。
- 节点只显示名称和短状态。点击一个节点才在图下显示一条详情与相关操作，同时高亮其上下游关系；一次只显示一个节点的详情。
- 用户只需要拖入资料、点节点查看、在输入框给要求或反馈。布局和依赖自动整理，不要求手动连线、配置端口或维护步骤表单。
- 新资料使用位置尚未确定时显示“待分配用途”，不能为了让图好看就把它连接到所有输出。缺少本计划所需来源时先补资料，不能继续按旧计划执行。
- 宽界面横向三层，窄界面分层堆放；缩略选区始终只是摘要，不因展开详细图就展示全文。
- 最新评审原型初始展开详图，便于查看此轮变化；点击“收起”即可体验日常轻量状态。正式产品默认展开状态留作偏好，不影响任务状态。

## 文件拖入和交付预判

- 文件默认以参考资料身份进入图，不能通过拖动改变当前文档的写入绑定。点击浏览也不等于授权修改。
- 使用稳定资源ID传递拖放，不把任意外部路径变成可读取资源。外部文件须先导入、读取并注册，再成为列表项。重复拖入只保留一个节点。
- 移出图只解除本次任务的参考关系，不删除文件。已有结果和实际修改记录也保留。
- 同一面板使用指针捕获完成拖放，兼容嵌入式页面不完整的浏览器拖放事件；跨面板仍可传标准DataTransfer。键盘操作提供等价的加入/移出按钮。
- 开始前显示预计类型，点击后查看完整文件名，例如预算明细表.xlsx、客户摘要.docx；按用户要求也可预判PPTX，或仅回答而不生成文件。必须带“预计”标识，不能伪装成已存在文件。
- 用户可以调整格式或取消某个预计交付。没有支持的工具时标明“不支持”，不擅自替换格式或显示可以开始。
- 资料版本、当前目标版本、要求、工具能力清单发生变化，都使旧预判失效。运行中的来源变更须先暂停后续动作，再准备新计划；已经验证的结果标记需要核对。
- 用户在输入框改了要求但尚未发送，也不能直接按旧计划开始。输入草稿、浏览摘要与拖动过程不应丢失。

实验层已增加只读的 `companion/agent_lab/preflight.py`：模型基于显式请求、来源摘要/版本、绑定目标和能力清单提出结构化交付预判。没有任何文件工具、任务状态写入或执行器权限，不根据关键词路由任务。宿主独立检查资源ID、文件名/类型、绑定范围、重复交付和能力支持情况。请求及全部版本组成预判指纹，用于拒绝过期计划。

只预判交付不需要先完成内容撰写；可以读资料解决的问题留给执行时核对。未指定的篇幅、风格或页面结构采用合理默认，不逐项打断用户。任务本身缺少关键目标时才追问。`can_prepare`仅表示预判没有阻碍，`execution_authorized`始终为false；不能拿模型预判当写入许可。

## 点击和反馈

- 点参考文件：只显示一条短摘要，相关节点突出；不替换正在修改的文档，也不占据一整列预览。
- 点当前文件：定位它的作用、选中范围和版本；选区内容仍是缩略。
- 点预期结果：明确显示“待生成”；有真实输出回执后才显示“已生成”。
- 在输入框给反馈：调整当前检查点，保持同一张图与任务。后续方向由用户消息决定；有歧义先澄清。
- 每完成一段，只更新当前文件节点的版本/进度和一句结果，原文在宿主中即时显示。不会为每一小步新添节点或长消息。
- 修改目标的切换必须有明确的重新绑定。浏览来源文件和选区变化不会隐式扩大写入范围。
- 当前文档检查完，继续完成后面的文件输出；每个文件结果出现时原位更新其节点，不另弹窗口，不逐个审批。

窄侧栏的日常状态保留紧凑文件流，文件名截短时提供完整名称提示；展开详细图后按来源、处理、交付分层排布。工作台与侧栏使用相同任务。展开列表、任务图、资料摘要或任务记录，都不替换输入框。

## 任务记录

默认只保留顶部历史图标。展开后每个任务一行：时间、任务名、状态。工具调用、模型重试、完整对话、逐段操作记录仍保存在内核供恢复与排错，不默认展示，也不能因界面省略而清空Agent上下文。

## 图与真实执行的关系

图不是文件执行器，也不能用画出的关系假装操作已经发生：

- 计划关系与执行证据分开。尚未生成的文件使用虚线和“待生成”，不能提供假打开入口。
- 图节点保留稳定资源ID，版本另记；文件改名后不因为名称变化变成陌生对象。
- 每次写入绑定资源、范围、预期版本和操作ID。读回成功后才更新节点的已完成状态。
- 连线来自明确的任务依赖或操作输入/输出记录。只有读过某文件，不足以证明所有输出都引用过它；不把“所有输入连接所有结果”当作已证实的数据血缘。
- 来源变化时，依赖旧版本的未执行动作失效；已有结果标注需要核对或更新，不能继续冒充新版本结果。
- 点击一个节点只查看；真正改变任务输入/目标使用独立的用户动作，不能靠视觉选中扩大权限。
- 停止保留已经验证的输出；恢复只补剩余项。待核实的写入暂停核对，不作为普通失败自动重放。
- 初始图中最多展示3份参考资料，更多资料聚合为“另外N份”；中间检索/计算步骤折叠，避免任务越长图越乱。需要排错时单独读取事件记录。

## 接入实现顺序

1. 接入只读预判，采用带版本的输入快照。接受计划前重新核对指纹，将用户接受的交付契约交给既有执行器；模型预判本身不能扩大读写权限。
2. 在现有任务状态上做只读图投影，映射来源、固定目标、交付物清单、检查点和实际输出回执。对缺失的关系保持“计划/未知”，不补造执行证据。
3. 同一输入框继续调用既有Agent工具循环；将“选区缩略”做在呈现层，完整授权内容按需提供给Agent，不把截断摘要当作全文。
4. 接上继续、停止和反馈；用原有稳定操作ID、来源复核和宿主独立读回控制写入。图不能直接绕过这些边界触发修改。
5. 复用同一真实WPS测试文档验收：读选区、逐段可见、反馈后改向、引用另一个文件、连续生成文件。另在工作台验证多个输入、多个结果和中途停止恢复。

本轮可交互原型演示持续可用的文件列表、真正的鼠标拖动、标准拖放数据、缩略、交付类型调整、逐段反馈及停止恢复。原型内使用示例状态，不调用API，不生成真实文件，也不接入原生应用。自由输入的新要求会明确留在“待Agent预判”，不会套用示例结果冒充语义识别。单独的只读预判模块已调用真实DeepSeek验证；它尚未接到正式界面或WPS，不能算新的宿主执行验收。
