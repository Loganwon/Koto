# 简洁文件任务交互

2026-10-20。对双入口设计的进一步精简。当前为交互原型与执行流程验证，未部署到正式Office/WPS侧栏。

## 日常只做三件事

1. 勾选或添加资料。工作台中资料保持独立左栏；窄侧栏展开独立的上方资料区。勾选表示只读引用，当前修改目标另行固定。
2. 在一个输入框中说要求或反馈。日常不选择Agent、协议、运行模式，不填写任务表单。
3. 看原文或结果文件。修改一段后，结果旁只有一个主操作“继续下一段”；后续有文件任务时，最后一个检查点显示“继续生成文件”。文件生成不中途逐个审批，完成项即时出现。

界面保留Koto、历史入口和两种尺寸的切换。任务标题从要求生成，不单独占一行。默认不显示模型状态、能力清单、连接调试、方向标签、反馈范围复选框、永久预览列或多套编辑按钮。需要查看来源时就地展开短预览，不替换对话。历史只读展开，保留当前任务、输入框和资料。

输入框在等待检查时明确提示“调整这段，或告诉我接下来怎么做”。最新消息由Agent理解；明确提到后续的约束持久保存，有歧义先澄清。输入反馈不自动批准下一段修改。修改目标或范围有冲突时先核对，不随点击资料或切换应用而改变目标。

## 文件执行保留在内核

界面删掉控件，不删掉执行合同：

- 读资料、计算、修改和生成仍由同一Agent与工具边界处理，不能用界面脚本关键词决定任务。
- 引用携带明确资源ID；本轮修改携带绑定范围与版本。资料内容不能扩大写权限。
- 原生局部修改成功读回后暂停；只读问答保留原目标与未完成项。
- 生成任务持续到要求的所有文件都有真实回执。文件存在不等于任务成功，还须可重新打开、内容符合要求且没有待核实动作。
- 界面按工具结果显示文件。模型说“完成”不直接改变完成状态。
- 停止取消尚未执行的动作，已经完成的结果保留；恢复只处理剩余项。结果不明的写入暂停核对，不当作普通失败重复执行。
- 应用内和工作台使用同一任务ID。切换入口不另起Agent，不清空草稿、引用和检查点。

## 本次实际执行证据

以用户已授权的DeepSeek配置执行四轮真实请求：

1. 读取项目资料，精简首段，并等待检查。
2. 用户要求统一使用“客户方”，同一输入口调整首段，保留第二段。
3. 用户确认后继续第二段，按资料更正研发123.45万元、运营67.89万元，并沿用称呼。
4. 用户确认后生成`预算.xlsx`、`客户摘要.docx`，核对数字与事实，完整结束。

8项结果检查通过。输出是实际XLSX/DOCX文件；编辑端使用JSON文档替身。该验证没有通过原型网页发送请求，也没有操作原生WPS，不能宣称已完成正式界面的端到端验收。记录：`.pytest_tmp/agent-simple-entry-20261020/file-flow-result.json`；文件位于其`real-file-flow/outputs/`目录。

正式接入时首先将这四轮操作跑过真实网页和同一份WPS测试文档，再验收多文件、错误恢复与Mac。现阶段不声称能保证任意文件或任意应用任务成功。
