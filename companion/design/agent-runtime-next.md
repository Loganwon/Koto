# 当前内嵌 Agent 的实现边界

更新：2026-10-25。Word/WPS 文字当前使用 `PaneTaskSession → NativeDeepEngine → NativeBroker`。
每个执行窗口600秒；`progress_window.py` 对超时但已有已验证文件/原文进展的任务允许自动续接一次窗口，两个窗口共享每轮模型60次、工具100次上限。用户停止、结果不明、检查待确认、权限关闭或无进展时不续接；不新增用户消息，只清理模型轨迹，依据真实任务与回执继续。时间边界在检查点执行，实际耗时计入验收等待。私有推理与工具回合保存在执行器检查点，JSON规划及核对经内部流式接收，预留推理输出额度并有界重试截断响应。传输帧32MiB、实际可见结果2MiB分别限制，避免正常推理流被误判正文超长。PPT页数区间由宿主硬校验；拒绝某次规划约束不再撤销整轮文件授权，显式只读模式及真正的文件权限拒绝继续关闭写入。
最终验收改用宿主编号的正文证据块：模型只选择块ID，程序从实际正文解析引文，不再让模型重打一遍长引文而产生省略号、换行或JSON转义错误。未知块ID、漏掉检查项或有内容遗漏仍拒绝完成。固定内容清单按文件分别编译，全部校验通过后一次保存，避免Word/PPT不同数量的要求相互串线。
本轮合同中的criteria须逐字对应真实要求或上一版合同片段（只允许去掉新增的末尾断句标点），不能把资料页码等细节变成用户未提的义务。明确的准确文字另保存原始用户回合及连续原句，由宿主在实际正文中直接检查；语义等价不能替代指定文字。生成文件、读取资料等执行行为由回执证明，不应要求把执行声明写入交付正文。提取这些条件仍依赖模型，需要独立质量检查。
原 2026-10-19 的独立验证规划已移入 [历史目录](archive/agent-runtime-plan-20261019.md)，不再作为当前接入进度。

执行前，交付预判与 `task_requirements.py` 的独立验收编译必须一致；明确的页数、字数、表结构、合计和来源要求由宿主登记。正文必留专名、日期、币种与限定单独检查。模型工具循环不能把漏登记解释成没有要求。

`contract_runtime.py` 让真实文件评测与生产使用同一合同编译流程。修订交付清单时，文件名、验收合同、字数及表结构在同一次状态事务更新，编译失败不提交半份清单。上一份完整合同随编译输入提供，防止长对话仅剩近期消息时忘记持续约束。

`acceptance_plan.py` 在写入前把当前合同和其生效回合之后的修改要求编译为固定编号的原子清单，并持久保存。更早要求保留为背景，避免已经归档的初稿章节在短版恢复时复活；显式只读模式的追问保留在历史中，不转化为文稿要求。内容项、纯运行约束、被真实较新引文替代的要求分别保存；全部原始索引必须覆盖。原文普通逐段写入和“继续”不会重建同一份清单。交付合同在回合中修订后，下一次写入前必须冻结新清单。

`fixed_acceptance.py` 对每份实际保存交付分批检查固定编号，每批最多20项。每项必须给真实连续引文或具体遗漏，程序推导是否允许完成；任何批次缺失、截断或存在遗漏都不能通过。仍需独立核对任务质量：模型可能把复合条件拆得不完整，也可能误解替代范围。不能把清单协议合格等同于内容必然正确。

`working_context.py` 将模型工作状态压到约24000字符预算；完整要求、查询和回执保留在任务存储，截断处明确提供读取入口。恢复时不再灌入完整历史状态。`read_query_result` 校验结果字节及来源哈希后按行列返回已保存查询，无需重复SQL；事实定位或单位错误返回实际行列与类型。它不替模型推断业务口径，不允许靠SQL别名伪造金额单位。

停止后的返回明确为“已停止”，不复用历史完成答复；下一次继续会清理旧模型轨迹并沿用真实任务状态。这是任务内中断恢复，跨服务重启的宿主绑定仍未实现。

显式只读追问已有交付时，`read_grounding.py` 通过正常工具重新读取至多8份当前文件，优先当前交付清单，核对哈希并携带实际指标。模型对话移除旧模型自述，保留真实用户要求、合同和历史读取工具；局部内容标明截断与后续位置。此机制降低旧答复污染，不保证所有答复事实正确；自由对话未声明为只读时仍沿用既有流程。

`query_units.py` 按真实 SQL 表达式及明确的来源列单位追溯单位。未知单位保持未知；无法追溯的金额不能由模型自行声明单位后放行。它不证明 SQL 选择的业务口径或来源本身正确。

`drafts.py` 保存当前稿、版本号及被替代稿标识；此前失败的候选不会覆盖修复稿。`draft_layout.py` 优先保留正文调整分页与来源注记位置，无法排下时才交给 `draft_composer.py` 做语义压缩及逐页分配。正文阅读顺序保持，只有来源注记可自由分配。模型建议不直接修改原文，发布仍经过权限、事实、字数和来源核对。

`artifact_text.py` 对本任务生成的 DOCX/PPTX 提供 SHA256、段落旧值核对及旧版保留；支持合并内容后显式清空冗余段落，复杂混合格式段落拒绝整段替换。不能据此声称可修改任意现有 Word/PPT 文件。

原文仍是固定范围、单片段写入、原生读回后检查。明确的继续操作进入完成监督；问答与反馈保持各自权限。重新预判建立新版本并归档旧验收，不能混用旧来源证明。

同一原生任务内，`native_read_context.py` 在回合开始重新核对已读来源的实时版本，并续接实际读过的有限片段及已持久查询结果，避免每次反馈清空证据。磁盘或未保存原生资料变化后不复用旧内容；写前仍核对来源。此续接不等于侧栏跨服务重启恢复。工具清单按原文检查点阶段开放，未检查完原文时不暴露文件创建；完成原文检查后重新开放连续交付。

`working_context.py` 仅将当前要求、约束、检查点、回执及草稿版本放入模型工作状态；历史、被替代稿和完整证据仍可通过工具读取。`inspect_source` 对普通工作表展示与默认查询一致的字段，坐标/缓存等特殊投影仍须显式采用返回的选项。`draft_editorial.py` 保留小数点、单位和原话，统一同一必留短语的空格/冒号写法，避免压缩后重复追加事实；语义压缩后的页标题依据实际分页生成，纯分页调整保留既有标题。

`user_requests.py` 在模型执行前持久保存真实用户要求及交互类型，显式“继续”不替代被中断的反馈。完成验收后才推进已接受回合的水位；停止、模型异常和上下文压缩均不能清掉未验收反馈。工作上下文展示未完成要求，长消息仍可经任务工具完整读取。最终 DOCX/PPTX 验收分别覆盖旧契约和每条未验收反馈，缺项或重复索引均拒绝确认完成；同一轮重复确认复用相同验收范围。该日志并不恢复跨服务重启的原生文档绑定。

`delivery_acceptance.py` 在 `complete_task` 前对已接受任务中的 DOCX/PPTX 做独立内容验收：读取实际保存的文件、宿主计数、最新原文和真实用户反馈，逐项核对已接受的要求。文件存在、字数正确和写前意图核对不能代替最终内容完整性。语义不合格返回可恢复诊断，要求修订已有文件后重验；取消、文件变化或验收响应不完整均不能记为完成。通过结果仅在文件、任务要求、原文及反馈均相同时复用。改名与复制同步对应交付要求。

这层仍依赖模型判断，可能误判；当前仅适用于有任务契约的 DOCX/PPTX 交付，解析正文上限10万字符。XLSX继续采用既有结构、数值及已登记内容检查。图片、复杂图形及视觉排版不在这层验收范围，不能据此宣称所有文件任务可靠。

`source_grounding.py` 追加宿主必查的来源归属项，将已登记的非表格资料真实文本和程序校验的计算结果提供给最终核对器，检查正文和表格对能力、对象及结论的归属。每文件20000字符、总计60000字符；较大资料优先最近实际读取的位置，明确标记部分覆盖。来源哈希在读取前后及模型核对后复验，缓存同时绑定来源证据。未登记来源、图片与原生逐段修改尚不覆盖，这仍不是形式化的事实蕴含证明。

`artifact_text.prepare` 在调用意图核对器前模拟全部段落修订，程序提供修订后整份文件的真实指标；不再让模型猜测改后字数。旧段落和SHA不符时不浪费核对请求。发布前仍重新加载并核对。`write_authority.py` 对否定权限的修改做一次独立对象范围复核，输入不含拟稿、计数或来源评价；若对象已获授权，本次内容否定仍保留，但作为可修正内容问题处理，不能错误撤销整轮权限。该机制不新增权限，也不自动执行被拒候选。

当前生产最终验收使用 `fixed_acceptance.py` 的宿主块编号协议；`acceptance_evidence.py` 的旧逐项引文协议仅保留兼容入口。符合项必须指向实际文件证据，缺失或冲突写入 issue；程序根据 issue 推导状态，模型不能另给相矛盾的通过标志或覆盖字段。虚构引文、缺字段、重复索引均不予确认。页数/字数仍由宿主核对。这能阻止“已承认漏项却打通过”的协议问题，但不证明模型一定找全所有语义条件；仍需独立任务质量复验。

`completion.py` 在回执版本核对后读回实际文件计数；`complete_task.saved_output_metrics` 返回最终页数、字数与对应 SHA256，最终答复不得引用尚未发布的拟稿计数。语义复合反馈中纯宿主计数及运行行为单独标为不适用，不能据此跳过正文内容条件。

Web 主程序仍使用 Core Kernel；Excel/PowerPoint 原生侧仍使用兼容会话。通用 MCP、代码沙箱、任意应用适配、Mac 安装与真机验收尚未完成。

仍需实现：侧栏跨重启的安全原任务恢复、完整输入队列、复杂结构编辑、更多未见任务与视觉排版验收。不得把测试夹具、真实模型文件测试和原生宿主验收混为一项。
