## 内嵌版本

Windows 开发安装：

```powershell
.\companion\addins\install.ps1 -ApiKeyFile "C:\path\to\key.txt" -Workspace "C:\工作资料"
```

默认脚本注册 Word、Excel、PowerPoint 开发清单，更新 WPS `publish.xml` 中仅名为 Koto 的文字加载项，并启动本机后台服务。可用 `-HostType Office` 只安装微软三类加载项，或分别指定 `Word`、`Excel`、`PowerPoint`、`Wps`。重复安装保留已有密钥文件与工作文件夹设置，除非显式传入新值。Office 首次从“加载项”中选择 Koto，此后使用 Koto 选项卡。WPS 入口位于“开始 → Koto 助手”，已在真实宿主点击打开；文字选区右键菜单也已显示“用 Koto 处理”。WPS 首次加载会显示允许/拒绝提示，需用户在宿主中确认；安装脚本不会自动退出用户应用。

Office 本地加载使用 HTTPS。安装脚本生成只包含 localhost / 127.0.0.1 的开发证书；默认不将其加入信任库。明确允许后可使用 `-TrustLocalCertificate` 完成当前用户证书安装。证书及私钥放在 `%LOCALAPPDATA%/Koto/Addin/`，与模型 API key 无关。`host.json` 只保存密钥文件路径，API key 在服务进程内读取，不回传网页。

WPS 安装还创建桌面与开始菜单的 `Koto（WPS）` 快捷方式。桌面快捷方式注册 `Ctrl+Alt+K`：先检查并按需启动本机服务，再通过 WPS 官方加载项调用协议执行固定的 `OpenKoto` 入口，不传入文件路径、不打开新文档。已存在的侧栏直接显示，保留当前对话与草稿。相同入口正在执行时忽略重复启动；调用超时不会再次派发，失败会提示检查宿主授权。“开始”功能区按钮已真机点击验证；全局快捷键、桌面入口及草稿恢复仍需单独完成原生操作验证。

安装默认添加当前用户登录后台启动项 `KotoEmbeddedService`，只启动本机服务，不自动打开侧栏；`-NoAutoStart` 可关闭。后台停止后也可双击根目录 `start_embedded.bat` 重新启动。开发卸载使用 `install.ps1 -Uninstall`，仅清理 Koto 的清单与所选宿主入口；`-HostType Both` 同时移除该开发证书和自动启动项。当前尚未制作正式安装包。

Word / WPS 文字内嵌读取目前覆盖正文和文档内表格文字；页眉、页脚、图片及嵌入对象明确列为未读取。WPS 可读取同一应用中已打开资料的未保存正文；Office 未保存来源需在另一已连接 Koto 侧栏的文件中读取，否则使用磁盘文件。来源写前复核与目标冲突检查保留。结构化表格预览、表格结构编辑、格式工具、保存和跨应用交付尚未接入新宿主适配器。

Excel 一次绑定最多 50 个选中单元格，逐格写入文字、数字、布尔值或明确公式，保留数字格式。保护工作表、合并区域、溢出数组、特殊数据类型和只读文件暂不写入。公式限于已声明的本地函数，不接外部链接、DDE、结构化引用和任意自定义函数；数字超过当前精度时拒绝静默舍入。全文按工作表读取值及公式，单表最多 2 万格、合计 4 万格，跳过范围明确返回限制。宿主要求 ExcelApi 1.13。

PowerPoint 绑定所选文字或文本框，以幻灯片与形状 ID 固定目标，逐处改文案；不调整布局、生成页面或改变表格结构。整框多段文字、混合字体、含超链接的页面和只读文件暂只读，可缩小为单段一致格式的文字选区。写前后核对文字与字体；全文最多读取 200 页、2000 个形状和 16 万字符，不含图表、图片、组合、表格、备注或母版。磁盘 PPTX 资料另可提取表格和备注。宿主要求 PowerPointApi 1.6。

每个可安全修改的段落、单元格或幻灯片文字片段写完就停下来，原生读回一致后才显示“已修改”。需要保留的表头等内容可跳过，显示“已保留”，仍等待用户继续。停止取消尚未执行的命令；已经交给宿主、但没有返回确认的写入显示“待核实”，不会自动重试。关闭或重载侧栏取消该连接的任务，不会把旧命令派发给新连接。

侧栏将文件和 AI 助手并排显示：左侧文件栏独立展开、收起，可拖动分隔线调整宽度（键盘左右箭头调整，Home 恢复默认）；右侧对话、修改预览和输入框始终保留。搜索文件名、点选最多 8 个资料即可引用，无需确认或切换页面；引用标签可单独移除，也可在文件栏清空。展开文件、改变宽度、开始新任务均保留草稿及未发送的引用。文件栏滚动不影响对话，发送及逐段反馈可直接进行。文档名、选区提示、当前对话和输入框连续排列，空闲时输入框靠近顶部。改动默认仅显示短预览，完整前后文字折叠；“下一处 / 完成本轮”和“调整这一处”区分操作。顶部“＋”提供新任务入口，重新绑定当前选区，完成后的历史不再重复显示同一句要求。

本轮实测发现并修复三类问题：

- 旧任务“删除n”的历史混入本次解释。`_task_history`仅承载当前任务上下文；界面完整历史保留，Agent可用只读`read_conversation_history`按需查询，并以已验证的修改前后文字解释本次改动。新任务清除过时恢复提示。

### 按顺序优化的实现状态（2026-10-19，界面 20261019.2）

1. **对话与检查点分离**：检查点记录上次已验证结果，明确标记不是实时原文。只读解释可以直接回答；询问最新正文事实仍需读取文档。模型声明要编辑后才验证绑定，实际写入前再次验证。绑定冲突后仍能只读对话，继续写入保持阻止。显式只读模式也保留原编辑任务和检查点；只读问题不加入后续编辑方向。Word 全文读取使用独立批次，不依赖片段范围仍有效。

   WPS文字写入另核对正文的精确替换差异：目标片段读回正确但其他正文发生变化时，结果仍为待核实，不开放自动重试或继续。该范围校验已通过模拟宿主故障注入，尚未完成原生版本验证；Word/Excel/PowerPoint仍按各自片段协议核对，不能宣称具有同一正文差异证明。
2. **持久化事件与恢复**：正式服务启用 `%LOCALAPPDATA%/Koto/Addin/activity.sqlite3`（其他平台使用用户数据目录），保存任务、轮次、模型/工具事件、写入请求、原生读回及近期对话，不保存模型密钥。先提交写入记录，再交宿主执行；记录失败时不开始写入，写后记录失败显示待核实。按文档恢复最近六轮对话及已确认结果，不恢复旧原生句柄，也不重放未确认操作。同一服务内的同一文档使用共享写入锁；这不是跨进程文件锁。未发送草稿尚未持久化。
3. **真实文件产物工具**：在已选择的工作文件夹里新建 DOCX（分节正文）、PPTX（最多20页标题/正文）和 XLSX（最多200行普通值）。输出经重新读取、非空检查、大小与SHA-256校验后返回文件回执；不覆盖同名文件，不自动打开。新文件暂不提供图片、图表、高级排版或公式生成。Word 接入原路径保存；WPS 接入原路径保存及PDF导出，均受宿主实际能力限制。Excel/PowerPoint原生保存和微软Office PDF导出尚未开放。未命名文件先由用户在宿主选择保存位置，避免弹出多个保存窗口。

验证记录位于 `.pytest_tmp/ordered-optimization/`：真实 DeepSeek 生成五页PPT、Word备忘录、数值预算表，以及失效绑定下只读对话/拒绝编辑共4项通过；20项基础真实模型回归通过。Word/WPS各一条完整侧栏模型链路通过；保存与PDF导出的生产JS适配器/RPC在模拟宿主下验证了磁盘结果及丢回应不重复执行。原生WPS仍加载旧版20261017.2，本轮没有重启服务或关闭文档，不能把这些结果记作新版原生验收。窗口枚举、截图可用，但可访问性树重复失真，侧栏右键无刷新入口，未继续注入键盘。

结构化分析新增显式 XLSX 读取口径：`formula_values=cached` 读取已有缓存（不重算，缺缓存保留空值），`expand_merged` 只展开真实合并区域，`header_mode=coordinates` 支持无规则表头的财务矩阵，`cell_range` 和 `include_provenance` 保留范围、原始行号与缓存缺失标记。`money_product_cents` 用十进制逐笔四舍五入到分，完整结果通过 `result_id` 导出；分析结果清单进入持久任务状态。正文与幻灯片新增宿主计数，写前核对器可看到实际字数，不依赖模型自报。

Deep Agents 增加不完整工具输出的有限恢复、与实际中间件步数匹配的循环预算、中文上下文压缩、无进度检查和重复错误停止。同一批并行工具的同类错误只计一次尝试，防止模型尚未看到错误就被提前终止。修复 Windows 拒绝请求时未消费请求体导致的连接重置。

使用工作区七份现有 DOCX/XLSX/PDF/PPTX、真实 DeepSeek API 测试三组复杂任务，源文件 SHA256 全部未变。首轮执行仅一组完整生成文件；修复后分别生成财务核对/尽调文稿、1719 行销售审计、三格式联合简报。独立核算确认金额 18,188,734.98 元和 16 个财务指标；仍发现摘要口径和数值比较错误（反馈后修订），以及短版字数约束与已有循环历史的收束失败。不能据此宣称任意复杂文件任务稳定通过。主环境回归 273 项通过、35 项条件跳过；实际 Agent 依赖环境另有九项机制验证，其中六项与主环境重复。

## 外置原型（保留的回归入口）

Koto 以独立浮窗连接 Windows Word / WPS 文字，文档的编辑、显示和保存由宿主完成。当前实现包括自动跟随选区、文档内表格、自己的模型 API、本地文件树和跨文件资料读取；AI 每完成一个段落或单元格内片段，就原生写入、读回并等待用户检查。独立 Agent 不导入旧 Koto Agent。

界面采用黑白灰，文件与对话使用同一套分页交互，不再通过主界面文件按钮外扩窗口。主界面只保留文档名、选区字数和一个输入框，初始要求与后续反馈共用输入框。默认不显示全文、路径或表格，点击选区提示才打开浮层预览。本节描述保留的外置原型；内嵌任务窗格进展见前文，全局快捷键收窄工作区和 Mac 连接器仍未实现。

## 启动

双击仓库根目录的 `start_companion.bat`，或使用项目虚拟环境：

```powershell
.\.venv\Scripts\python.exe -m companion
```

点击右上角模型名称进入设置，查看接口、模型及密钥来源（例如 `DS_KEY.txt`），或更换配置。密钥仅保存在本次进程，不回传界面或写入日志。也可显式使用现有配置或纯文本密钥：

```powershell
.\.venv\Scripts\python.exe -m companion --use-koto-api
.\.venv\Scripts\python.exe -m companion --api-key-file "C:\path\to\key.txt" --workspace "C:\工作资料"
```

环境变量为 `KOTO_COMPANION_API_KEY`、`KOTO_COMPANION_BASE_URL`、`KOTO_COMPANION_MODEL`。基础地址不包含 `/chat/completions`。传入的密钥文件会从工作文件树和 Agent 读取范围中排除。

## 使用

1. 打开 Word / WPS 文档，选中要修改的文字；不选时处理光标所在段落。发送时读取最新内容。
2. 点击“文件”或输入框的“＋ 文件”，打开工作文件夹。目录可折叠、可按文件名搜索，多选资料后点击“引用 N 个文件”。引用在输入框上方显示为标签，可逐个取消。文件旁的打开按钮使用系统默认应用打开它。
3. 直接提出要求，例如“读取预算表中的研发金额，补进选中段落”，或“这份文档的表格说明了什么”。Agent 自行调用读取、搜索、回答或修改工具，无需选择工作模式。
   Enter 发送、Shift+Enter 换行；中文输入法确认候选字时不会误发送。发送后立即显示状态，发送按钮变成停止。回答以流式显示，工具修改只在完整校验后原生写入。
4. 一个片段写入并原生读回后立即停下来。查看宿主中的实际结果，或展开“查看改动”。
5. 同一输入框填写反馈：发送会重做当前段；“保留并继续”将反馈应用到下一段；“新要求”会在下次发送时重新绑定当前文档和选区。文件夹和近期对话在本次进程中保留。
6. 停止阻止后续写入；保存仍使用 Word/WPS 原有操作。任务固定原文档，切换查看资料不会把进行中的修改写到另一份文档。

## Agent 与读取范围

Agent 循环为：按需找文件、读取或搜索、提出一个片段的修改、核对来源与目标、原生写入、读回、等待反馈。一次最多 18 轮模型请求、48 次工具调用、8 个参考文件，超出会暂停。本地文件内容、文档和工具结果是数据，不作为 Agent 指令执行。

选区处理不再预先读取全文：先传入当前选区，全文及表格按需读取。Agent 可分页读取或搜索整个原生正文（含表格文字），以及宿主可提供的页眉、页脚、脚注、尾注、批注和文本框区域。每份快照提供覆盖范围、版本和未解析项目；没有读取的区域不能报告为已读取。轻量监控只读取选区、正文前 4000 字符和基本状态，不遍历表格；展开选区预览才读取结构化表格，预览最多 6 张表、300 格及 18000 字符。

参考格式为 DOCX、XLSX、PPTX、PDF、TXT、MD、CSV、JSON。DOCX 包括正文、表格、页眉页脚及包内注释区域；XLSX 读取全部工作表（包括隐藏表）、单元格地址和公式，公式缓存为空会明确保留为空，不自动计算；PPTX 读取幻灯片顺序、文字、表格文字与备注；PDF 只提取已有文本。图片没有 OCR，图表与嵌入对象未解析，旧 DOC/PPT/XLS/WPS 二进制文件暂不作为磁盘参考文件解析。

同一连接器已知的 Word/WPS 会话中，参考文档已打开时优先读取未保存的原生内容。每次写入前重新核对本轮实际读取的来源版本；来源或工作文件夹变化时拒绝旧结果。来源只读，不会自动保存或修改。未读取文件只显示“未读”状态；文本提取完成仍与图片等内容的完整解析区分。

文件树仅显示所选文件夹内的支持格式，排除隐藏目录、Office 临时锁文件、逃逸工作区的链接和显式密钥文件。最多显示 1500 个文件，超出明确提示；Agent 的列表支持分页及文件名查找。单个参考文件最多 32 MB，Office 解压读取最多 64 MB，XLSX 单表范围最多 100 万格，超过限额不会报告读取完成。

## 当前边界

- 外置原型通过 Windows 自动化对象接入 Word / WPS 文字；内嵌加载项的独立能力与验收进展见前文。Mac 尚未验收。
- 每次绑定最多 50 个片段，每段最多 8000 字符；写入为单段完整替换，不插入段落或表格结构。
- 支持格式一致的正文和单元格内文字。域、图片、超链接、内容控件和混合格式片段可只读，修改要求需缩小选区。只读问题不会调用写入工具。
- 用户修改相同片段后拒绝旧结果；用户修改其他位置可以继续。原生写入不自动滚动或抢焦点，定位由用户点击。
- 轻量跟随和界面刷新间隔约 0.12 秒，不监听全局键盘、不在用户每次输入时调用模型。按发送、继续或重做才调用所配置的 API。宿主忙时仍可能延迟。
- 原生连接通过宿主运行中的自动化对象；多个独立进程的会话覆盖有限，以显示的文档名和选区核对目标。
- 暂无自动跨目标批量写入、批量保存、跨应用交付、完整选择性撤销、崩溃恢复和正式插件分发。关闭程序不会退出办公应用。
