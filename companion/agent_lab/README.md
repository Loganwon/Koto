# 下一轮 Agent 内核验证层
长任务执行窗口为600秒；`progress_window.py` 仅在已有可核对文件/原文进展、用户未停止、权限有效、结果明确且不在等待用户检查时，允许超时后自动续接一次600秒窗口。两个窗口共享每轮模型60次、工具100次的上限，不新增用户消息；同一回合重建模型轨迹并沿用真实任务、回执和来源。没有进展及第二次超时不自动续接。时间边界在检查点执行，验收等待计入实际耗时。每轮真实测试记录自身预算，旧冻结清单中的240秒不能代表新运行。流式接收区分传输帧与实际正文大小，私有推理不进入可见内容预算。JSON核对为推理预留输出额度，截断时仅重试只读核对，不重放文件动作。PPT支持页数区间；规划参数被拒绝不会把整个任务锁成只读。

显式只读追问已有交付时，`read_grounding.py` 通过正常工具重新读取至多8份文件，优先当前清单，附带当前哈希和实际指标；局部内容明确标注截断及后续位置。模型上下文移除过往模型自述，真实用户要求、合同、回执与历史读取工具仍保留。此机制降低旧答复污染，不是事实正确性的保证，也不覆盖未声明为只读的自由对话。

`source_grounding.py` 在生成的 DOCX/PPTX 最终验收时重新读取已绑定的非表格资料，将来源文本、来源哈希与已核对的计算结果传给不可省略的来源归属检查。每份最多20000字符，总计60000字符，超出明确标记截断；大资料优先最新实际读取的位置。资料在读取或验收期间改变均不能确认完成。这是模型辅助的语义核对，仍可能漏判；未登记来源、图片和原生逐段编辑不在这层范围。

生成文件的局部修订会在意图核对前，在内存中应用段落修改并计算修订后整份文件的字数/页数；SHA与旧段落不符时不调用核对模型。实际发布前再次核对候选及文件版本。`write_authority.py` 对模型判为无权限的文件修改，单独以动作对象与真实用户要求复核权限，不向其传入拟稿。若只是内容问题，本次候选仍拒绝，但不把整轮锁成只读；真正缺少授权仍关闭写入，不跳过内容及发布检查。
官方 DeepSeek 执行链开启低强度推理，并在工具回合与检查点中完整保留私有reasoning_content；修复已固定SDK读取该字段但请求转换时丢失的问题。推理正文不进入侧栏答复或评测报告。合同及验收保持独立请求；能力和时延仍须以实际任务质量衡量。接口依据见 [DeepSeek官方协议](https://api-docs.deepseek.com/guides/thinking_mode/)。
结构化读取新增保存的 DOCX 顶层表格：显式0起始table编号、真实表头和来源哈希，不查询普通段落或未保存内容。money_cents支持严格合法的千位分组金额，非法格式仍保持NULL。查询结果索引不再因新预览覆盖早期全量结果；长时间没有推进时允许有限上下文恢复，不自动发布文件。
最终内容验收采用宿主正文块ID，真实引文由程序解析；模型不再复述长引文。逐文件编译固定清单后统一提交，检查清单与证据块都不能由模型自行省略。

合同criteria必须对应真实用户原话，逐字条件保存真实消息引用并由宿主检查；来源页码不能由编译器自行变成新的用户要求。长程测试入口为 `companion/benchmarks/long_horizon.py`，覆盖销售全量审计、财务矩阵和八轮跨文件改向/中断继续。所有失败目录保留，`grade.py` 独立读取输出并核对质量，不能只按会话“无异常”计成功。

维护说明（2026-10-25）：本轮加入执行前固定编号的内容清单、分批最终验收、最新合同生效回合、显式只读提问与修改要求的区分，以及有界的模型恢复上下文。文件评测也经过生产任务合同；交付清单变化与对应合同在同一事务更新。`read_query_result` 可读取已持久查询的有限行列，错误的事实绑定返回真实行列、类型和单位，未知金额单位仍拒绝。

停止后不会复用上一轮“已完成”答复，继续时从任务状态与真实回执重建模型上下文。它不恢复跨服务重启的原生文档绑定，也不表示 Word/WPS 本轮真机已通过。固定清单编译与验收仍由模型完成，可能漏解或误判；编号完整只能阻止协议上的漏项，不能证明语义覆盖完整。

这是可独立评测的 Agent 内核。2026-10-21 起，DeepEngine、交付预判及任务状态层已通过 `PaneTaskSession/NativeBroker` 接入 Word/WPS 原生侧栏，安装使用独立的 `.venv-agent` 环境。Pi 仍是对照候选。下面的 CLI 评测只操作指定验证目录中的资料、JSON 文档替身和生成文件，不启动 Office/WPS；真实宿主结果另外记录，不能互相替代。

## 已实现

- `DeepEngine`：实际使用 Deep Agents 0.7.28 和 LangGraph SQLite 检查点；原生改动后停止本轮，下一轮保留会话；可在评测中强制上下文压缩。
- `PiEngine`：实际使用 Pi Agent Core 1.3.0，通过私有标准输入/输出调用同一套 Python 工具；消息逐轮持久化；临时网络错误最多重试两次模型生成，不重做已完成工具。
- `TaskStore`：目标、约束、待办、原生检查点、文件回执和历史分别保存。一次回答或唯一段落修改结束不会自动结束整个任务。跨进程锁确保一个任务只有一个执行者。
- `ToolBroker`：两套候选共用资料读取、精确计算、单片段替换、真实 Word 表格及基础 DOCX/XLSX/PPTX 生成、输出读回与完成核对。
- `inspect_source`：读取真实文件能力、工作表、投影字段、行数及有限预览；无规则表头返回显式坐标投影建议。SQL错误携带真实字段/支持函数及下一步工具，第二次相同错误可触发有限上下文恢复，不自动改写用户要求。
- `CompletionSupervisor`：已授权执行中，模型只交付一部分就结束时，按真实缺项最多提醒两次继续；未完成不能靠最终回复记成成功。只读、普通后续问答、原文检查点、取消及待核实状态不触发追加写入。
- `check_completion` 与 `complete_task` 共用 `completion_status`：检查实际输出SHA256、未完成步骤、原文范围及已登记质量约束。模型自行标记待办完成不能代替文件回执和读回。
- `delivery_acceptance.py`：`complete_task` 再读取有任务契约的实际 DOCX/PPTX，独立逐条核对内容要求及真实反馈。内容漏项返回修订诊断，修订后重新验收；验收期间停止或文件改变均不能记录完成。通过缓存绑定文件、契约、原文和反馈。当前10万字符上限，不覆盖图片、复杂结构或视觉质量，也不是事实正确性的绝对保证。
- `set_workbook_schema`：将用户明确给出的工作表、固定列名/顺序及行数存入任务；不允许擅自翻译表头或添加未要求的表。创建/修订的工作簿发布前、任务完成前均检查真实结构，原始文件不受影响。
- `observations.py`：计算/测量及等价数据查询的重复观察检测。查询身份按真实结果和来源版本计算，不因SQL空格或预览长度不同就当新进展；来源或数据改变不会被当成旧观察。
- 局部草稿修复仍限制为本轮最多两次模型提议；第二次修复使用第一次提议及实际不合格原因，不从原始长稿重新开始。提议不发布，真正创建仍经过权限/事实核对。
- `revise_deliverables`：最新用户明确取消、添加或改名交付物后，经独立核对更新任务清单；检查清单版本并保留变更记录，不能自行删掉未完成项来宣布成功。
- `query_data`：在内存 SQLite 中对显式指定的 CSV/TSV、JSON 对象数组、无公式 XLSX 做关联、去重、筛选和聚合。金额用整数分计算，非法金额保持空值。查询不具备宿主文件、网络、扩展或 Shell 权限。
- 分析结果以校验过来源版本的 `result_id` 持久保存；模型只看预览，生成工作簿使用完整结果，重启后可继续，不把预览当成全量资料。
- `create_workbook` 支持多个工作表及显式公式；普通字符串始终作为文本。只允许本地纯计算公式，不计算公式缓存。`revise_workbook` 支持修改本任务已生成的 XLSX，校验 SHA256 和目标单元格旧值，保留旧版本，读回后生成新回执。
- 本轮明确只读时不暴露写工具，执行层也拒绝写入。自动模式写前另用真实模型核对“最新用户消息与本次动作”；这不是关键词意图路由，语义核对也不是绝对保证。
- 文件输出和原生写入有稳定动作编号。已验证动作只返回旧回执；崩溃留下的已开始、未确认动作转为待核实，不自动重放。
- `BoundTextDocument` 已通过 `NativeDocument` 接入 Word/WPS 原生侧栏，接受已有连接器及固定选区，不重新打开文件、不使用全局 COM 对象、不绕过宿主写入。
- 原生回合续接会重新核对实际已读片段及查询的来源版本，保留仍有效的证据；变化的来源不沿用旧事实。原生检查点阶段仅开放相应工具，全部片段检查后再开放文件生成。工作上下文只列当前状态，完整历史与当前草稿通过工具按需读取，不把过时草稿重新灌入系统指令。
- 写前核对接收本轮真正读取的来源片段（最多12段，每段2000字，标明截断）及最近30个精确计算结果，核对金额、单位、日期和限定。事实不符允许修正后重核，权限拒绝仍关闭本轮写入。计算结果单独留痕。这是语义核对增强，不能视为事实正确性的数学保证。
- 原生 `preserve_fragment` 核对实际原文后记录明确保留的片段，不向宿主写入相同文字；不会因部分原文无需修改而阻止整个任务结束。检查中的只读追问保留当前检查点。

## 独立安装与启动

使用项目已有 venv 创建独立环境，避免升级正在运行的插件依赖：

```powershell
.venv\Scripts\python.exe -m venv .pytest_tmp\agent-lab-env
.pytest_tmp\agent-lab-env\Scripts\python.exe -m pip install -r companion\agent_lab\requirements.txt
npm.cmd ci --prefix companion\agent_lab\pi --ignore-scripts --no-audit --no-fund
```

Node.js 需要 22.19 或以上。当前实测 Node 25.8.2。NPM 锁文件只属于此验证层；Python 主要依赖也已固定版本。本机验证环境为复用已安装文档库而启用了 `--system-site-packages`，上面的干净安装路径不依赖该设置。

创建任务（目录应当专用于验证）：

```powershell
.pytest_tmp\agent-lab-env\Scripts\python.exe -m companion.agent_lab.cli `
  --directory .pytest_tmp\my-agent-task --engine deepagents `
  --api-key-file C:\path\key.txt `
  --goal "精简首段，确认后生成摘要.docx" `
  --message "先精简首段，等我检查。" --require-output 摘要.docx
```

首次运行会创建 `document.json` 文档替身。资料放进 `references/`，生成结果进入 `outputs/`，任务编号保存在 `task.json`。不要把验证根目录指定为真实工作资料夹。

同一个任务中追问或继续；任务编号来自前一次结果：

```powershell
# 只读追问不清除原任务和检查点
.pytest_tmp\agent-lab-env\Scripts\python.exe -m companion.agent_lab.cli `
  --directory .pytest_tmp\my-agent-task --engine deepagents `
  --api-key-file C:\path\key.txt --task TASK_ID `
  --mode read --message "解释刚才改了什么。"

# 用户明确确认或要求调整后，释放上一个检查点，继续原目标
.pytest_tmp\agent-lab-env\Scripts\python.exe -m companion.agent_lab.cli `
  --directory .pytest_tmp\my-agent-task --engine deepagents `
  --api-key-file C:\path\key.txt --task TASK_ID --acknowledge `
  --message "确认了，继续完成最初要求的后续工作。"
```

将 `--engine` 换为 `pi` 可测试轻量方案。一个任务固定使用一种引擎；本轮不支持在执行途中把某引擎的未完成调用交给另一引擎。

## 原生接入与剩余边界

只读交付预判 `preflight.py` 基于真实用户要求、来源摘要和版本、绑定范围及工具能力清单，建议原文修改和待生成文件的类型/名称。已接入生产侧栏的任务图与执行器。独立校验文件名、资源ID、能力、重复交付和目标绑定，执行前再核对来源与原文版本；预判本身没有写工具，`can_prepare`不是写入授权，`execution_authorized`始终为false。原文 edit 与另建文件 create 分开，即使用户不生成文件也可修改原文。

1. 已映射侧栏会话、任务及本轮权限，回答追问保留目标；仍需扩大真实任务样本。
2. Word/WPS 已验证未保存选区读取、原生逐段写入、反馈改向。服务重启或界面重载会保留历史和已完成文件，但尚未自动恢复原生任务绑定；不能把 CLI 的检查点恢复等同于侧栏原任务恢复。
3. 明确运行中输入队列及取消行为；当前同一任务一次只接受一个活动回合，提供停止后改向，尚未实现完整后台消息队列。
4. 接入有边界的代码执行、检索和外部工具。当前未开放任意代码执行、浏览器、MCP 或微信投递，不能称为已具备任意文件任务能力。
5. 扩大未见任务、长时间运行与压缩后恢复测试，再分别做 Word、Excel、PowerPoint、Mac 原生验收；目前表格修订只覆盖本任务生成的 XLSX，不能声称可改任意现有工作簿，Word/PPT 复杂结构修改也未补齐。

API 密钥只在模型客户端内存和 Pi 私有标准输入中传递，不进入任务状态、命令行参数或报告。模型完成不等于任务完成；输出必须有实际文件和校验回执。语义正确性仍需要独立评测。

## 2026-10-22 完成能力补强

本轮保持侧栏交互不变，补强所有引擎共用的执行边界：

- `content_checks.py` / `set_content_checks`：将关键数值绑定到持久查询的真实单元格，使用 Decimal 换算人民币单位及比例，并按指定精度舍入。将真实引文绑定到已保存资料，正文必须包含对应引用和文件标识；发布前与完成前都检查，资料变更会使旧检查失效。登记项按稳定 ID 合并，存入任务数据库，重启后保留。验收不能塞入文档或幻灯片标题。只核对已登记项目，不能证明 SQL 语义正确、全部事实真实或来源本身可信；来源单位仍经语义核对器检查。尚未支持未保存的原生参考文档版本作为持久引文依据。
- `file_operations.py`：`copy_reference` 保留原件、逐字节复制到任务交付目录；`copy_artifact` 复制已验证交付；`rename_artifact` 改名并同步清单、字数/结构/内容验收。操作要求当前 SHA256、不覆盖，不接受越界路径、扩展名伪转换或任意外部移动，当前不含子目录整理。DOCX/XLSX/PPTX/PDF/CSV/TSV/TXT/JSON、单文件最多16MiB。改名后的旧操作编号不能把不存在的旧文件伪报为成功。
- `TaskStore.receipt` 将交付清单和待确认动作结果在同一 SQLite 事务持久化。新进程取得独占任务锁后，只在保存回执、清单和实际文件哈希完全一致时确认动作，继续未完成交付而不重放。没有保存回执的中断、原生正文待核实写入、外部改变的结果仍保持 uncertain，不盲目重试；这不等于原生宿主绑定自动恢复。

`source_tools.py` 抽出来源工具的只读处理，避免继续扩充工具入口文件。复制、改名与验收工具继承同一轮只读限制、最新用户授权核对、取消与动作编号约束。原生接入使用相同工具定义，但每项新增能力仍需分别进行实际宿主验收。
