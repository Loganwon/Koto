# Koto Office / WPS 助手

当前入口是 Office / WPS 内嵌侧栏。`start_companion.bat` 和
`start_embedded.bat` 均启动同一个已安装服务，不打开文档、不恢复执行旧任务。
在宿主中点击 Koto 打开侧栏。初次安装使用 `addins/install.ps1`。

## 当前界面

Word / WPS 文字使用 `ui/workflow.html`：宿主中的当前文档和选区是默认上下文，
侧栏提供一个输入口及润色、检查表述、总结入口。快捷操作只填写要求，发送后
沿用现有的只读准备和开始执行流程。参考资料、任务详情、历史和设置按需打开；
当前文档无需导入 Koto，不在插件中另建编辑器。

执行记录来自已完成工具操作，模型文字不充当回执。实际修改每段写入并读回后暂停，
修改前后对比默认展开，用户可定位到原文、输入反馈或继续下一处。
切换宿主文档会明确提示旧任务的绑定范围，不随文档切换而更换修改目标。

`ui/legacy/` 是尚未迁移的 Excel / PowerPoint 兼容界面和旧版回归资源。
HTTP 兼容路径保留，避免破坏已安装加载项。旧浮窗仅通过
`python -m companion --legacy-floating` 显式进入，不再是正常启动路径。

## Agent

`agent_lab/` 提供当前 Deep Agents 执行器、持久任务状态和统一工具边界；
`pane_task_session.py` / `pane_task_tools.py` 连接原生文档。原生修改与
文件生成使用真实回执，模型回复不能代替完成证明。`tool_contracts.py`
是中立的工具定义，当前执行器不再依赖旧浮窗 Agent。

执行前单独编译任务验收，明确的页数、字数、表结构、合计、来源及必留词由程序登记。
查询金额按真实表达式与来源列单位核对；修复草稿有版本，避免重复使用旧稿。
已生成的 DOCX/PPTX 可按段落旧值及 SHA256 修订并保留旧版；混合格式和复杂对象不做整段替换。
这些检查仍不能证明全部业务语义正确，完整任务质量需要独立核对。

真实用户反馈独立持久保存，停止或模型上下文重建不会丢掉尚未验收的修订要求。
最终 DOCX/PPTX 内容验收同时逐条检查旧要求及未完成反馈，不能只凭旧交付齐全宣布完成。
符合项必须给出实际文件引文，遗漏须明确登记；程序推导通过状态，拒绝相矛盾的通过标志。
最终完成回执返回已保存文件的页数及字数，答复不能把拟稿计数当成最终结果。

当前界面重载或服务重启仍不能自动恢复原生任务绑定。旧接口返回明确升级提示，
当前工作流不会进入旧会话方法。停止/继续与跨重启恢复须分别验收。

共享工具入口的草稿测量和文件创建已分别归属 `agent_lab/drafts.py`、
`agent_lab/artifact_creation.py`；历史设计见 `design/archive/`。

`benchmarks/` 是可选的真实文件比较工具，外部框架不进入生产依赖。
测试在隔离副本中执行，保存请求、运行记录和独立验收结果；编辑检查点
测试使用持久文档夹具，不能据此宣称通过原生 Office / WPS 验收。

历史实施记录存放于 `design/archive/implementation-history-through-20261021.md`。
历史记录中的旧启动方式、版本和成绩不代表当前入口或当前验收结果。

插件界面回归：`node scripts/ui_office_addin_smoke.cjs`。它运行生产 HTTP 路由、
鉴权桥接、原生宿主适配器和任务侧栏，通过进程管道连接以适应禁止本机 TCP
访问的测试环境。模型与 Word/WPS SDK 为测试替身；它不构成真实宿主验收。
