# Koto 稳定性契约

本文件描述 Agent 底座与 Addon 运行时必须长期保持的行为约束。

## 任务状态

- `TaskLedger` 是计划、取消、终态和恢复信息的持久化所有者；
- 取消请求可在任务登记前写入，并在进程间、重启后保持可见；
- `completed`、`failed`、`cancelled` 采用 first-terminal-wins，后续事件不能改写终态；
- 计划更新是字段合并事务，禁止用缺省值覆盖已有检查点；
- 缺少人工审批处理器时任务保持 `waiting`，不得自动通过或报告完成。
- 同一运行的事件在 TaskLedger 同库 journal 中先分配唯一序号并持久化，再发布；实时流与回放不得重新编号；
- 浏览器断线与用户取消分开处理，恢复订阅不得重新提交原请求；
- Kernel 和文件专属工作流从持久检查点恢复，保留工具权限、文件版本和原质量门；未知写入结果或人工修改冲突必须核实后继续。

## 工具副作用

- 只读工具可以按 deadline 放弃迟到结果；
- 进程内写入工具不能在线程仍运行时报告超时；
- 非幂等步骤不自动重试；相同写入型 Kernel 调用在一次任务中不得重复；
- Addon 写入工具必须接收必填 `idempotency_key`；
- 文件写入经过同目标跨进程锁、回滚备份和原子发布；失败结果恢复原文件。

## 原版文档工作台

- 模型文字增量、完整工具请求、编辑器实际变化和源文件提交是不同事实；未完成参数不能触发工具；
- 活文档工具需要宿主绑定的浏览器、文件身份和实际编辑器版本；模型参数不能授予自身作用域；
- 排队成功不代表已执行，编辑成功不代表已保存；保存成功需要源版本检查、真实提交和读回证据；
- 同一可信请求的重复操作 ID 不重复执行；不同请求的操作 ID 独立；已有未确认写操作时不得换 ID 重试写入；
- 源文件或文件句柄内容已被外部修改时保留当前编辑稿并拒绝覆盖；另存副本不能改写或劫持原文件绑定。

## Addon

- 注册、启停和删除都会推进持久化 revision；每个 Worker 调用前校对 revision；
- manifest 的超时、最大并发、结果大小和 RAG 条数在运行时强制执行；
- 连续失败触发贡献级熔断和退避，健康状态降级并暴露错误；
- 生命周期和贡献调用写入 SQLite 审计库，可通过管理员审计接口查询；
- 禁用后的 Addon 在所有 Worker 刷新后不可规划、不可检索、不可进入工具目录。

## 状态文件与启动

- JSON 状态统一使用跨进程锁、同目录临时文件、`fsync`、原子替换和有效备份；
- 主文件与备份同时损坏时隔离损坏文件并报错，不得静默返回空状态；
- 本地模式默认绑定 `127.0.0.1`；通配地址且未认证时启动失败；
- cloud/production 模式必须启用认证并配置至少 32 字符的 JWT 密钥。

## 发布门禁

- 全仓 pytest 必须可完成 collection；
- Python 单元/集成测试、前端 typecheck/Vitest、发布源码回归和浏览器 smoke 均为独立门禁；
- 测试中的 TaskLedger、Addon、用户、摘要等状态必须写入 pytest 隔离目录；
- CI 不得引用已删除的 Skill、Agent 或测试文件。
