Real Workflows

先覆盖每天真的会发生的文件任务。

Koto 把成熟能力集中在 Office 文件真实写回、长文分步处理和可核验的工作流上；弱项不硬包装成卖点。

Word / DOCX

审校、批注和版本对比

  • 合同、报告、论文草稿可以读取段落并写回内容。
  • 支持 Word 原生批注、清除审阅标记和两版 DOCX 差异标注。
  • PDF 原文 + DOCX 译稿可分批对照审校，适合长书稿和翻译稿。
Excel / Data

表格分析进入报告

  • 读取 Excel/CSV，检查工作簿结构、公式和外部链接。
  • 用 Python 沙箱做统计、图表和数据清洗，再把结果写入文件。
  • Excel 表格和图表可以作为真实 Word 表格/图片落到 DOCX。
PPT / Slides

汇报材料快速整理

  • 解析 PPTX 文本，更新现有页文字或追加总结页。
  • 统一主题、字体、配色和安全版式，默认保留原页数和核心内容。
  • 适合工作汇报、项目复盘、答辩和课程展示草稿。
Research

科研学习材料分步处理

  • 长 PDF 按页窗读取，逐步写成读书笔记或章节摘要。
  • 论文、课堂资料、实验表格可以组成可追踪的本地资料工作区。
  • 适合先读、再提炼、最后写入 Word 的学习闭环。
Text / Code

选区改写直接写回

  • TXT、Markdown、CSV、JSON 和代码片段可读取指定行。
  • 选中内容润色、改写或替换时，精准替换原选区并自动备份。
  • 适合会议纪要、README、研究笔记和轻量配置文件。
Local-first

过程透明，不做黑盒交付

  • 执行步骤、工具调用、目标文件和写回结果都可见。
  • 关键任务会核验 file.changed，而不是只给一段“已完成”。
  • 本地优先，必要时再切换云端模型处理复杂语言任务。
现阶段不把 OCR、复杂 PDF 原文编辑、参考文献管理、LaTeX 编译和高级 PPT 动画当作主能力；这些可以辅助处理，但不作为稳定交付承诺。
White-box Agent

文件助手是核心产品，不是附属功能。

它把 AI Agent 从黑盒任务变成白盒实时交互：当前文件可见、步骤可见、提案可见、写回结果也可见。

Black box

传统 AI 任务流

  • 把任务丢进去，等一个最终结果
  • 中间怎么处理基本不可见
  • 不知道会改哪里，也不知道如何写回
  • 文件往往只是附件，不是交互现场
Koto

白盒文件助手

  • 选中内容后立刻进入实时互动
  • AI 的规划、提案和执行步骤直接展示
  • 先看改动，再决定是否应用到文件
  • 应用即写回，所改即所得
