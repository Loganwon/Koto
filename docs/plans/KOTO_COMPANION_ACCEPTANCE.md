# Koto 原生文字协作最小验收方案

版本日期：2026 年 10 月 16 日，Asia/Shanghai。正式验收用例保持 NOT_RUN。当前转为 Word/WPS 内嵌侧栏，旧浮窗的开发验证不能替代新宿主适配器验收。开发证书信任和 WPS 首次加载确认仍待用户授权。

内嵌新增放行条件：从宿主自己的 Koto 选项卡展开侧栏；不开外置浮窗；两个文档各开侧栏时目标隔离；关闭侧栏后旧命令不重放；排队修改在停止后不执行；已经派发但未读回的写入显示待核实且不重试。下文完整流程需在内嵌侧栏重新执行。

Harness 新增验证：模型按需维护和调整短计划；文件事实通过工具读取，计算通过计算工具完成；错误参数可以修正；长结果可以按 evidence_id 取回；重复无进展有界暂停；最新反馈进入下一轮；计划完成不冒充宿主写入验证。新增工具必须登记能力、作用范围和真实验收用例，不能只修改系统提示后宣称已支持。

本方案只验证接入文字宿主、编辑中调用 Agent，以及逐段修改及时可见。关联[近期里程碑](KOTO_COMPANION_ROADMAP.md)中的 M0 至 M2。原[完整验收方案](future/KOTO_COMPANION_ACCEPTANCE.md)作为后续参考，不是当前放行条件。

## 一条完整验收流程

准备一份有 3 个待修改段落、一个基础表格和一张图片的测试文档，并保留原始副本。使用真实 Word 或 WPS 文字，浮窗连接真实模型 API。

1. 用户选中第 1 至 3 段，唤起浮窗，要求“逐段改得简洁一些，每段完成后让我检查”。
2. 等待模型时，在任务范围以外的第 4 段输入一条唯一标记，确认宿主仍可正常操作。
3. AI 完成第 1 段后，结果直接出现在原生文档中；此时第 2、3 段仍未修改。
4. 用户保留第 1 段，并要求“后面先说结论，再解释原因”。
5. AI 按新方向修改第 2 段，完成后立即显示并再次等待反馈。
6. 用户点击停止，验证第 3 段保持原样，不再产生新写入。
7. 检查第 4 段的手动输入、表格、图片和无关段落格式都保留。
8. 使用宿主正常保存并重新打开，核对最终内容。

每个已接入宿主执行 5 次，使用唯一标记区分。需要一次原生应用与浮窗同屏录像，以及修改前后文件和脱敏动作记录。模拟编辑器或聊天框内的生成文字不能代替原生文档结果。

## 最小用例

| 用例 | 阶段 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| TEXT-01 | M0 | 绑定打开的文档，读取选区及尚未保存的手动修改 | 内容来自原生会话，包含未保存输入，目标和范围准确 |
| TEXT-02 | M0 | 通过连接器替换一个指定片段，再读回结果 | 修改出现在真实宿主；读回与预期一致，只修改指定片段 |
| TEXT-03 | M0 | 打开两个同名文档；运行任务时切换到另一个文档 | 修改仍作用于明确绑定的目标，原选区不会被浮窗焦点丢失 |
| TEXT-04 | M1 | 配置自己的接口地址、密钥、模型，并用自然语言发起修改 | 完成真实 Agent 工具调用和原生写入；API 错误时无假成功 |
| TEXT-05 | M1 | 等待模型时，在任务范围外输入唯一标记 | 宿主可继续编辑，用户输入保留，浮窗不持续抢焦点 |
| TEXT-06 | M2 | 对 3 段文本逐段处理，检查第一段完成时的文档 | 第一段完成就可见；默认等反馈，不等全文完成才回填 |
| TEXT-07 | M2 | 保留第一段后，改变后续方向 | 第一段保留；下一段遵循新方向，旧计划未开始的写入不再执行 |
| TEXT-08 | M2 | 在执行中请求停止，再检查剩余段落 | 接收停止后不再派发新写入；进行中的原生动作状态真实可见 |
| TEXT-09 | M2 | Agent 读取后，用户先修改同一目标片段，再允许写入 | 检测变化，重新读取或提示冲突，不覆盖新输入 |
| TEXT-10 | M2 | 修改普通正文，比较表格、图片和无关段落，再保存重开 | 无关内容和格式保留，宿主保存后的文件有效 |
| TEXT-11 | M2 | 注入网络失败、宿主失联和只读状态 | 已完成部分保留，失败位置清楚，不继续盲目写入或假报完成 |
| LIVE-01 | M0 | 不点击读取按钮，移动光标、改变选区并输入未保存文字 | 浮窗自动更新文档名、位置、选区和文字；跟随过程不调用模型 |
| LIVE-02 | M0 | 保存文档，再切换到另一文档 | 保存状态和当前上下文更新；已运行任务仍绑定原文档 |
| TABLE-01 | M0 | 打开含普通表格、合并单元格的 Word/WPS 文档 | 可读到单元格内容及行列关系，预览与原生内容一致；截断明确标识 |
| TABLE-02 | M1 | 在同一对话框询问表格项目的金额，无需切换模式 | 模型回答来自真实单元格，未修改文档 |
| TABLE-03 | M2 | 只修改一个单元格内的段落 | 该格文字更新，邻格、表格结构及其他正文和图片保留 |
| FULL-01（新增，NOT_RUN） | 完整读取 | 选中第一段，询问只在全文末尾出现的标记 | 能读取并定位末尾内容，不能因选区而失去全文访问 |
| FULL-02（新增，NOT_RUN） | 完整读取 | 使用超过当前截断长度的长文，包含后半部表格、批注或脚注 | 支持范围全部读取并有覆盖记录；不支持或失败部分明确列出，不假报全文可用 |
| FILE-01（新增，NOT_RUN） | 本地工作区 | 展开本地文件列表，多选引用、预览和取消引用 | 资料选择与读取状态真实，未读完时不显示全文可用；预览不改变当前编辑文档 |
| FILE-02（新增，NOT_RUN） | 多文件连续处理 | 结合三个资料更新复盘，再接着更新整改清单 | 两个目标依次更新，参考资料和用户反馈持续保留，已完成内容不被重做或覆盖 |
| FILE-03（新增，NOT_RUN） | 多文件连续处理 | 保存本轮两个已修改文档，再切换查看 | 只保存本轮目标，内容与未保存的原生状态处理正确；未命名文档由宿主确认位置 |
| FILE-04（新增，正式 NOT_RUN） | 跨文件补充 | 另一份参考文档磁盘值为 120，在 Word/WPS 中未保存地改为 9876；要求补进当前三段选区 | 读取最新 9876，第一段先写入并等待，其他两段不变；反馈后第二段按新方向写入，第三段不变，来源未改动 |
| FILE-05（新增，正式 NOT_RUN） | 资料变化 | Agent 读取参考后、写入前修改参考资料；或切换工作文件夹 | 拒绝旧结果；当前目标未被旧数据修改，来源和用户输入保留 |
| FILE-06（新增，正式 NOT_RUN） | 极简交互 | 展开真实文件夹和子目录，点击文件引用，用同一框发送要求与反馈 | 目录可折叠，非示例数据；界面仅一个可见对话输入框，原生每段完成都可见；缩窄窗口时发送按钮仍可见 |

前三条对应固定操作验证，TEXT-04 起使用真实 Agent。每条用例至少运行 3 次；完整流程的 5 次运行另行记录。

## 及时可见的判定

一次 AI 修改的交付单位是一个段落或明确文本片段。写入完成后立即读回并更新浮窗状态，原生文档已经显示修改后，才报告这一部分完成。

暂定目标：普通短段落从连接器接受有效写入到原生画布可见及读回完成不超过 2 秒；停止请求的本地反馈不超过 200 毫秒。各测 10 次并保留原始耗时。模型生成耗时单独记录；宿主忙或正在执行不可中断操作时如实显示状态，不提前报告停止完成。

用户正在其他段落输入时，显示修改状态和可点击定位入口，不强行滚动或移动用户光标。可以在浮窗呈现模型生成进度，但不将逐 token 改写原生正文作为完成条件。

## 放行与证据

每次运行记录用例、宿主、软件版本、输入标记、实际步骤、预期与实际结果、证据位置和 PASS、FAIL、BLOCKED 或 NOT_RUN 状态。失败记录保留，修复后追加复测。

对应宿主的 M0 至 M2 用例和完整流程全部通过，才完成该宿主的最小里程碑。出现改错文档、覆盖用户输入、无关内容丢失、结果未显示却报告完成、停止后继续派发旧动作中的任一项，均不得放行。
