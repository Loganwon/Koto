# Koto 原生文字协作最小里程碑

版本日期：2026 年 10 月 16 日，Asia/Shanghai。当前主线已切换为 Word Office.js / WPS JS 内嵌任务窗格，宿主对象、侧栏会话和模型后台分离。插件清单、本地服务、宿主读写协议及 harness 代码已实现，Word 清单校验和自动测试已通过；真正的内嵌真机验收等待本地开发证书与首次加载授权。此前外置原型的开发记录保留，不作为内嵌放行凭据。当前实现与试用方式见 [Companion 说明](../../companion/README.md)。

新增近期里程碑：M3 在真实 Word/WPS 中完成侧栏首次加载、选区跟随、逐段写回、反馈和停止；M4 扩展独立 harness 的实际工具，覆盖跨文件核对、计算、文档结构操作、导出和保存等任务，每项以真实工具结果验收。已经实现的短计划、工具注册、参数修正、计算、证据分页和循环检测属于 M4 基础能力，不代表所有任务均已支持。Mac Word 采用同一 Office.js 协议继续适配；Mac WPS 另行核实官方支持，均需真机验收。

近期主流程：用户在 Word 或 WPS 文字中正常编辑，从宿主内的 Koto 侧栏调用自己的 API，让 Agent 修改指定文字；AI 每完成一小段，结果立即出现在同一份原生文档中，用户可评价并改变后续方向。下文 M0–M2 的浮窗描述为此前开发基线，M3 在内嵌侧栏复验同一流程。

文档编辑与显示始终由 Office/WPS 承担。新 Agent 独立设计，旧 Koto 只提供产品思路。Windows 与 Mac 都是目标平台，使用共用的任务和修改协议、分别适配宿主；当前开发机上的 Windows 流程先验证，Mac 同等流程逐项接入并用真机验收。

## 当前交付范围

| 能力 | 最小要求 |
| --- | --- |
| 接入宿主 | 连接已打开的 Word/WPS 文字，绑定当前任务的文档和选区 |
| 浮窗调用 | 一个对话入口，显示目标文档、执行状态、当前修改与反馈按钮 |
| 自有 API | 配置接口地址、密钥和模型，支持一次真实的 Agent 工具调用流程 |
| 原生上下文 | 读取当前选区或明确指定的段落，包括尚未保存到磁盘的内容 |
| 自动跟随 | 持续读取当前文档、光标、选区和保存状态；用户发送时获取最新内容 |
| 文档内表格 | 保留行列关系读取单元格、提供只读问答、逐个修改可编辑单元格内文字 |
| 完整读取 | 原生正文可全文分页和搜索；宿主提供的其他区域和参考文件提供覆盖范围与未解析项目，界面预览仍有界 |
| 本地文件工作区 | 类 VS Code 可折叠目录树，点击文件引用到同一输入框；Agent 按需读取并核对资料版本，支持从其他文件补充当前选区 |
| 小步修改 | 以一段或一个明确文本片段为单位执行；一次完成就写入、读回并展示 |
| 并行编辑体验 | 模型请求期间宿主仍可编辑；用户编辑其他位置时不抢焦点 |
| 用户反馈 | 保留继续、调整本段、改变后续方向、停止；每段完成都可介入 |
| 内容保护 | 不改错目标，不覆盖用户新输入，不改写无关内容和格式 |

按本次用户要求，本地文件列表、多文件引用与多文档连续处理已重新纳入当前设计范围。Excel 等文件可以先作为参考资料读取，原生编辑连接器、微信拖放、PowerPoint、长期任务调度、完整崩溃恢复、插件市场和正式发布体系仍留到后续。实现和放行状态须与已完成的外置原型分开记录。

## 用户操作流程

1. 用户在 Word 或 WPS 文字中打开文档，选中需要处理的内容。
2. 唤起 Koto 浮窗，提出要求，例如“逐段润色，每段完成后让我检查”。
3. 浮窗显示本次绑定的文档与范围。用户继续在原生应用中输入或编辑其他段落。
4. Agent 读取原生内容，完成一个片段，通过连接器写回同一文档。
5. 连接器读回结果，浮窗显示已修改的位置与简短说明。用户可点击定位。
6. 默认逐段检查：用户保留继续、提出修改意见或改变后续方向。
7. 用户停止任务后，不再派发新的写入。正常保存仍使用宿主原有流程。

用户点击浮窗输入框之前应保留原选区与文档身份。切换到另一文档查看资料，不会自动改变正在运行的任务目标。

## 最小执行设计

执行链路为：原生文档上下文，Agent 决定下一小步，检查目标内容是否变化，通过宿主写入，读回验证，向用户展示这一部分，接收反馈。

一个完整段落或明确文本片段是交付单位。模型生成期间可以在浮窗显示进度，但不逐 token 改动原生正文，也不等全文处理完才一次性回填。每次写入都须能对应到具体目标与结果。

用户修改了 AI 即将写入的位置时，旧修改先停止，重新读取后调整方案。用户编辑其他位置时，AI 可以继续处理自己的目标片段。发生同区域冲突时，不整份覆盖，也不全局锁住文档。

同一文档的 AI 写入有序执行。改变方向后，旧计划尚未开始的写入作废；已经进入宿主执行的动作据实显示为完成中或待核实。停止接收反馈和停止原生写入不是同一件事。

最小实现采用一个主 Agent 和明确的文档工具。先完成读上下文、替换片段、读回、定位和停止控制；运行时锁定版本后使用。当前阶段不以复杂多 Agent 或完整持久化平台作为前提。

已实现的跨文件循环提供文件列表、参考文件分页读取/全文搜索、当前文档分页读取/全文搜索、只读回答和当前片段替换。显式 `@"文件路径"` 引用未读取时禁止写入；实际读取的来源在写入前再次核对版本。每段完成后暂停，反馈进入下一轮读取和修改。参考文件在已知宿主会话中打开时优先读取未保存内容，来源始终只读。

## 三个近期里程碑

| 里程碑 | 交付 | 放行条件 |
| --- | --- | --- |
| M0 接入真实文字宿主 | 连接 Word/WPS，读取当前选区和未保存内容，执行一次固定文本修改 | 目标绑定正确，修改直接出现在原生文档；具体宿主与版本有记录 |
| M1 编辑中调用 Agent | 浮窗接入自己的 API，通过 Agent 工具完成一次原生文本修改 | 真实模型调用成功；等待模型期间用户仍能编辑；不丢失原选区 |
| M2 逐段可见与反馈 | 多段任务逐段写入、显示、暂停检查并接受新方向 | 第一段完成就可见；后续按反馈处理；停止有效，用户内容与无关格式保留 |

M1 依赖 M0 的目标绑定与读写，M2 依赖 M1 的真实工具执行。时间安排在 M0 完成后根据实际连接器工作量确定。先展示真实宿主上的最小流程，再扩展其他能力。

## Windows 与 Mac 的执行顺序

| 宿主组合 | 当前计划 | 验收记录 |
| --- | --- | --- |
| Windows Word | 原生连接、浮窗调用与逐段反馈已实现 | 真实 API 桌面流程开发验证通过，正式验收待执行 |
| Windows WPS 文字 | 独立连接器复用同一任务协议 | 真实 API 桌面流程开发验证通过，正式验收待执行 |
| Mac Word | 复用任务协议，实现本端桥接并执行相同流程 | 未执行，需真机 |
| Mac WPS 文字 | 单独确认可用的原生接口，再完成相同流程 | 未执行，接口待验证 |

近期 Windows 原型可按实际通过的宿主单独标记完成；不能据此标记 Mac 已支持。两端最终是否完成，以同一最小流程在对应宿主真机上的结果为准。Mac WPS 的接口验证失败时，明确保留缺口，不能用只读预览或覆盖磁盘文件替代原生编辑。

Office 的具体接口能力按宿主与 API requirement set 检查，Windows 的 COM/VSTO 不进入共用核心。[Office 平台说明](https://learn.microsoft.com/en-us/office/dev/add-ins/overview/office-add-ins)。WPS 公开加载项概述列出 Windows/Linux，Mac 路线须独立核实。[WPS 加载项概述](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/wps-integration-mode/wps-addin-development/addin-overview)。

## 本轮完成标准

用户能保持文档打开并正常编辑，在浮窗中提出修改要求，看到 AI 完成的第一段立即出现在文档里，再通过一句反馈改变后续处理。目标绑定、用户输入和无关格式保持正确。

只对真实执行并通过验收的宿主组合宣告完成。具体步骤和失败判定见[最小验收方案](../plans/KOTO_COMPANION_ACCEPTANCE.md)。
