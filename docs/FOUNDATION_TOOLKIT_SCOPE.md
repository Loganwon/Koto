# Koto Foundation 基础工具包能力边界

状态：`koto.foundation@1.0.0`
工具来源：`toolkit:koto.foundation`
当前固定工具数：32

## 结论

基础工具包已经能够承接大部分通用办公文件任务，但不能单独完成银行开户、客户背景
调查、法律知识检索或核心数据库操作。它是 Agent 的“手和基础办公能力”，不是银行
业务规则、专业知识和外部数据本身。

## 当前能力

| 能力 | 状态 | 当前范围 |
|---|---|---|
| Office/PDF/文本读取 | 可用 | DOCX、XLSX、PPTX、PDF、TXT、MD、CSV、JSON 的受控读取与窗口化提取 |
| Office 文件写入 | 可用 | DOCX、XLSX、PPTX、文本创建和修改，写入后产生结构化变更记录 |
| 文件审阅与比较 | 可用 | 多文件比较、DOCX 差异、批注计划、Word 批注、抽取和标注 |
| 财务表格处理 | 可用 | 工作簿结构、公式、外链检查、财务表异常审计、单元格写入 |
| 工作区文件操作 | 可用 | 列出、复制、创建和打开工作区文件 |
| 文件转换 | 条件可用 | 依赖 Microsoft Office、LibreOffice 等本地转换器 |
| Python 沙盒 | 条件可用 | 依赖 Koto 沙盒运行时，适合数据处理、图表与临时文件生成 |
| 完成核验 | 可用 | 写任务完成前检查目标文件和结构化变更证据 |

能力目录由 `foundation/capabilities.py` 提供，工具 allowlist 与结果契约由
`foundation/catalog.py` 提供；新增或删除工具但没有同步能力分类时，契约测试会失败。

## 对此前银行场景的覆盖判断

| 场景 | 当前覆盖 | 仍缺少的层 |
|---|---|---|
| 银行员工日常文件整理、读取、摘要、改写和报表生成 | 大部分具备 | 具体模板留在宿主配置；外部专业能力由 Addon 提供 |
| 合同比较和在 Word 中写入差异意见 | 基础能力具备 | 法律判例、法规时效、条款风险规则需要法律 Addon/RAG |
| 基于内部制度知识库回答问题 | 文件读取具备，检索闭环未具备 | RAG Addon、权限过滤、引用证据和索引更新机制 |
| 扫描证件或影像件 OCR | 未具备稳定基础能力 | OCR Provider、图像质量检测、字段置信度和人工复核 |
| 客户背景调查、工商/制裁/黑名单比对 | 未具备 | 银行业务 Addon、授权数据源、实体消歧和查询审计 |
| 对公账户自动开户 | 不能单靠工具包完成 | 确定性工作流、KYC/AML 规则、双人复核、核心系统 API、幂等和补偿 |
| 直接查询或修改银行数据库 | 未接入 | 数据库/API Addon 协议、最小权限、只读/写入分级、脱敏和审计 |

因此，如果“之前的任务”指通用文件处理底座，当前已经覆盖主要动作；如果指完整银行
业务自动化，则目前只完成了文件与执行基础层，不能宣称已经覆盖绝大多数业务要求。

## 正确分层

1. **Agent Kernel**：任务循环、预算、工具策略、错误和事件协议。
2. **Foundation Toolkit**：通用文件、工作区、转换、沙盒和结果核验。
3. **专业 Addon**：OCR、RAG、法律、工商、KYC/AML、数据库和外部 API。
4. **业务工作流层**：开户步骤、审批状态机、人工复核、补偿、幂等和审计留痕。

下一轮基础工具包优先补 OCR Provider 接口、统一文档块/表格/图片读取结果，以及大文件
分页与证据定位；RAG 和数据库不塞进基础包，而通过 Addon 协议接入。

统一的数据目录、字段权限、Live Database、证据血缘和数据访问网关设计见
[`INFORMATION_MANAGEMENT_SYSTEM.md`](INFORMATION_MANAGEMENT_SYSTEM.md)。
